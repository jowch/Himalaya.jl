# I4.4 — Index Cutover (Phase 4 closeout) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Retire the legacy three-card Index workspace now that the focus workspace (`/sample/:sampleId`, I4.1/I4.2/I4.3) replaces it — delete `IndexPage` + its Index-only composition, redirect `/index*` → `/sample/...` (or `/samples` when no sample is known), retire the `activePage:"index"` branch so a stale persisted value can't strand the user, repoint the legacy Index E2E/Vitest specs at the focus workspace, and add the Phase 4 mocked Playwright q-link spec the issue calls for.

**Architecture:** Mirror the I1.7 inspect-cutover precedent (PR #206, merged) but for `"index"`. Four moves: **(1) Route redirect** — replace the four `/`, `/index`, `/index/:experiment`, `/index/:experiment/:sample` `<Route>` entries (which render `PageBody`) with `<Navigate replace>` redirects landing on the focus workspace. **(2) State retirement** — narrow `PageId` from `"index" | "compare"` to `"compare"`, drop `"index"` from `VALID_PAGE_IDS`, and flip the `coerceActivePage` fallback target off the now-dead `"index"`. **(3) Deletion** — `IndexPage.tsx` and the components imported only by it, plus the legacy Index unit/E2E specs. **(4) Parser cleanup** — because `PageId` losing `"index"` forces `tsc` errors at every `page: parsed.kind` / `activePage`-typed site, drop the `kind:"index"` parse arm and the dead `"index"` branches in `useStateFromUrl`/`useUrlFromState`/`useGlobalShortcuts`/`TabRocker`/`StaleUrlPage` (the I1.7 "Option A" pull-forward precedent — narrowing the union is *this* issue's job, not I5.3's).

**Tech Stack:** React 18 + TypeScript strict (`exactOptionalPropertyTypes`), react-router-dom v6 (`<Navigate>`, `useParams`/`useNavigate`), Zustand (persisted store + `coerceActivePage` + `mergePersistedState`), Vitest + React Testing Library (JSDOM, MemoryRouter), Playwright (mocked, `page.route` + `page.addInitScript`).

**Issue:** #181 (I4.4). Depends on I4.2 (#179) + I4.3 (#180), both merged. Unblocks I5.1. Direct issue.

### The redirect-target problem (the one genuinely new wrinkle vs. I1.7)

I1.7 redirected `/inspect*` → a **static** path (`/samples`). Our focus workspace is **per-sample** (`/sample/:sampleId`), so there is no single static landing path. The legacy Index URLs are:

| Legacy URL | Carries | Maps to |
|---|---|---|
| `/` | nothing | `/samples` (corpus contact sheet — there is no "current sample" to focus) |
| `/index` | nothing | `/samples` |
| `/index/:experiment` | experiment slug only, no sample | `/samples` (focus needs a sample id; an experiment-only URL has none) |
| `/index/:experiment/:sample` | experiment + sample **slugs** (not ids) | the focus workspace, but the route wants a numeric `:sampleId` — slugs must be resolved first |

**Decision D2 (resolved below):** redirect the three sampleless legacy URLs (`/`, `/index`, `/index/:experiment`) statically to `/samples`, and for the slug-bearing `/index/:experiment/:sample` render a small **resolver redirect** component (`IndexSlugRedirect`) that calls `api.resolve({experiment, sample})` to get the numeric sample id, then `<Navigate>`s to `/sample/:id` (falling back to `/samples` on 404, error, or a `sample_id`-less success body). This preserves old `/index/<exp>/<sample>` deep-links (the permalink contract) by landing them on the focus workspace. **Bare `/` also redirects to `/samples`** (master-plan §4.1: the app home is the corpus contact sheet, not Compare).

## Decisions

> **All decisions below are RESOLVED** (frontend-reviewer PASS-WITH-NITS round, grounded in master-plan §4.1). No open questions remain for execution. The `+ /` redirect target is also resolved (→ `/samples`). The PR body still records them so the `review-pr` reviewer can confirm scope.

**D1 — `coerceActivePage` fallback + default `activePage` retarget to `"compare"`. → ACCEPTED.**
`"index"` is retired, so it can no longer be the fallback (it's not a `PageId`). The only surviving `PageId` member is `"compare"`. Set both `coerceActivePage`'s fallback (`state.ts` L39) and the initial-state default (`state.ts` L289) to `"compare"`. Rationale: (a) it's the only type-valid choice; (b) it's transitional — I3.6 retires `"compare"` next and re-homes the fallback again, and I5.1 deletes the whole `activePage` model; (c) **critically, with the bare-`/` redirect resolved to `/samples` (below), this default never drives a user landing** — the URL always wins because `/` redirects to `/samples` and Compare is URL-owned. The persisted-activePage coercion to `"compare"` is purely a type-valid fallback that no user ever observes as a page. **Rejected:** a non-`PageId` sentinel — adds a type the dying model doesn't need.

**Bare `/` redirect target → `/samples` (RESOLVED).** Master-plan §4.1: the shell's home is the corpus contact sheet; routing a cold `/` to Compare contradicts that. So Task 3's root branch `navigate("/samples", {replace:true})` and Task 4's `<Route path="/">` redirect to `/samples`. This is what makes D1's `"compare"` default a pure internal type artifact (above).

**D2 — Redirect mapping for `/index*`. → KEEP the `IndexSlugRedirect` resolver (NOT the blanket redirect).**
- `/`, `/index`, `/index/:experiment` → `<Navigate to="/samples" replace/>` (no sample id to focus).
- `/index/:experiment/:sample` → the **`IndexSlugRedirect`** component: read `:experiment`/`:sample` via `useParams`, call `api.resolve({experiment, sample})`, then `<Navigate to={'/sample/' + sample_id} replace/>`; on 404/error/missing-sample_id `<Navigate to="/samples" replace/>` (see the undefined-guard MUST-FIX in Task 4 Step 1). While resolving, render `<ResolvingFallback/>`. Preserves old slug deep-links onto the focus workspace (permalink contract). The blanket `/index*` → `/samples` alternative was **rejected** — it breaks the `permalinks.spec.ts` round-trip intent (slug URLs should reach the same content).

**D3 — `PageBody` fate. → KEEP a slimmed `PageBody`.** Drops the `activePage==="index"` branch + `IndexPage` import; retains the `resolving`/`staleUrlContext` handling and the `*` catch-all (now `<Navigate to="/samples" replace/>`). Full `PageBody`/`AppShell`/`WorkspaceGrid`/`TabRocker` deletion is explicitly **I5.1's** scope (issue-map §11 I5.1: "delete the old AppShell shell body, WorkspaceGrid, TabRocker, the activePage model"). **Do NOT pull it forward.**

**D4 — `StaleUrlPage` unknown-path CTA. → navigate to `/samples` ("Go to Samples").** Today it sets `activePage:"index"` ("Go to Index"). With Index retired, the CTA navigates to `/samples` (corpus home) via `useNavigate(..., { replace: true })`, relabeled "Go to Index" → "Go to Samples". §4.1-consistent with the bare-`/` target. Keeps the back-button-trap fix (replace mode) intact.

**D5 — q-link spec. → ALREADY SATISFIED; Task 9 is verify-only.** `e2e/qlink.spec.ts` already exists (I4.3) and covers the q-link cross-highlight on the focus workspace. The issue's "add a Playwright mocked spec for the q-link" criterion is met by it. **Do NOT duplicate** — Task 9 only confirms (and extends only if it turns out thin).

**CorpusTopbar inert "Index" tab → LEAVE inert (RESOLVED).** `CorpusTopbar.tsx` L17 has `{ id: "index", label: "Index" }` with no `to` (renders disabled). No honest per-sample `to` exists at corpus level — wiring it needs a "current sample" concept the corpus shell lacks. Outside the cutover. **Leave untouched; note it in the PR body** (Task 11 Step 2).

import { useEffect, useState } from "react";
import { Navigate, useParams } from "react-router-dom";
import * as api from "../api";
import { ResolvingFallback } from "./ResolvingFallback";

/**
 * IndexSlugRedirect — I4.4 (#181). Old `/index/:experiment/:sample` deep-links
 * carry slug names; the focus workspace route wants a numeric :sampleId. Resolve
 * the slugs via /api/resolve, then redirect to /sample/:id. On 404/error, land
 * on the corpus contact sheet (/samples). Index is retired; this only preserves
 * old permalinks.
 */
export function IndexSlugRedirect(): JSX.Element {
  const { experiment, sample } = useParams();
  const [target, setTarget] = useState<string | null>(null);

  useEffect(() => {
    let cancelled = false;
    (async () => {
      if (experiment === undefined || sample === undefined) {
        if (!cancelled) setTarget("/samples");
        return;
      }
      try {
        const body = await api.resolve({ experiment, sample });
        if (cancelled) return;
        // Undefined-guard (frontend-reviewer MUST-FIX): ResolveSuccess.sample_id
        // is `number | undefined` (api.ts ~L900). A success body without a
        // sample (e.g. an experiment-only resolve) would otherwise build
        // "/sample/undefined". Treat a missing sample_id like an error → /samples.
        setTarget(
          "error" in body || body.sample_id === undefined
            ? "/samples"
            : `/sample/${body.sample_id}`,
        );
      } catch {
        if (!cancelled) setTarget("/samples");
      }
    })();
    return () => { cancelled = true; };
  }, [experiment, sample]);

  if (target === null) return <ResolvingFallback />;
  return <Navigate to={target} replace />;
}
