# I4.3 — Focus-workspace q-link — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tie the focus-workspace surfaces by a hovered q-value: hovering a trace peak marker, or a detector ring, highlights the matching feature on the other surface. Implemented as an **ephemeral `hoveredQ` Zustand field** (excluded from `partialize`) + a **rotation-aware ring overlay** on `FocusDetectorPanel`'s detector image, wiring the trace `TraceViewer` as the q-source and the detector rings as both source and sink — without bypassing the `QNumInput` focus-gate.

**Architecture:** `hoveredQ: number | undefined` joins `hoveredIndexId`/`hoveredPeakId` as an ephemeral client-state field — declared in the store interface, defaulted to `undefined`, given a named setter `setHoveredQ`, and **omitted from the `partialize` projection** (the same way the existing two `hovered*` fields are: they are simply never listed in `partialize`, so adding `hoveredQ` requires NO persist `version` bump). `TraceViewer` gains an additive optional `onHoverQ?: (q: number | null) => void` prop, fired from its existing per-mousemove cursor handler (peak-snapped) — absent-prop = today's behavior, so the legacy `/index` path is unchanged. A new `DetectorRingOverlay` renders an SVG ring per peak q inside `FocusDetectorPanel`, positioned by a **normalized q→radius map** (there is no detector geometry in the data model — see *Load-bearing facts*), and **mirrors `DetectorImage`'s auto-rotate transform** by sharing the rotation-decision constants/helper rather than re-implementing or editing `DetectorImage`'s rotation core. The hovered ring/peak lights in the accent color on both surfaces.

**Tech Stack:** React 18, Zustand (`useAppState`, named actions, `partialize`), Observable Plot (TraceViewer overlay), SVG ring overlay, `ResizeObserver` (DetectorImage rotation), Vitest + RTL + JSDOM, Playwright (mocked spec).

## Load-bearing facts the implementer must know

1. **The ephemeral-field precedent is `hoveredIndexId` / `hoveredPeakId`** (`state.ts`). They are:
   - declared in the `AppState` interface under a `// ephemeral (not persisted to localStorage)` comment (state.ts ~L81–83),
   - initialized to `undefined` in the store body (~L283–284),
   - given trivial named setters `setHoveredIndex` / `setHoveredPeak` (~L324–325: `set({ hoveredIndexId })`),
   - and **absent from the `partialize` projection** (state.ts ~L531: `partialize` lists only `username`, `firstName`, `lastName`, `activeExperimentId`, `activeSampleId`, `activeExposureId`, `activePage`, `tutorialSeen`, `theme`). Persist `version` is `3` and **stays 3** — omission from `partialize` is the entire exclusion mechanism; there is no per-field "ephemeral" flag and no `version` bump.
   `hoveredQ` follows this pattern exactly. **Do not add it to `partialize`.**
2. **`TraceViewer` already computes a cursor q on every mousemove.** Its overlay effect (TraceViewer.tsx ~L646–669) has `onMove` → `requestAnimationFrame(drawCursor)`, and `drawCursor` (~L626) does `const q = invertQ(plotEl, relX)`. `onLeave` (~L652) hides the cursor. This is the q-source seam: fire the new `onHoverQ` callback from here (q on move, `null` on leave). `invertQ` casts the Plot scale's runtime `.invert` (the documented Observable Plot pattern in components/AGENTS.md). **Peak-snap:** the acceptance says "hovering a trace **peak**" — so emit the nearest-peak q when the cursor is within the existing `CLICK_TOLERANCE_PX` of a peak triangle (reuse `nearestPeak`/the peak pixel cache the overlay already builds), else emit the raw cursor q. (Decision: emit raw cursor q too, so the detector ring tracks the cursor continuously — confirm in open decisions.)
3. **`DetectorImage` auto-rotate** (DetectorImage.tsx): a `ResizeObserver` on the wrapper sets `layout.orient` to `"landscape"` when `window.innerWidth >= 1400` (`ROTATE_MIN_VIEWPORT`) AND `containerAspect > imageAspect * 1.25` (`ROTATE_THRESHOLD`); in landscape it applies `transform: rotate(90deg)` + swaps `maxWidth`/`maxHeight` on the **canvas**. CSS-only rotation doesn't change the canvas bounding box — that's why it's JS. **The ring overlay must apply the same `rotate(90deg)` (and the same caps) when the detector is in landscape**, or the rings will be unrotated over a rotated image. We do NOT edit `DetectorImage`'s rotation logic; instead we extract the two constants + the orient-decision into a tiny shared helper (`lib/detectorOrient.ts`) that both `DetectorImage` and `DetectorRingOverlay` import, so the two stay in lockstep. (`DetectorImage` keeps its own `ResizeObserver`/state; the refactor only moves the *pure* decision function out — a behavior-preserving extraction, covered by the existing `DetectorImage.test.tsx` staying green.)
4. **No detector geometry exists.** There is no beam center, pixel size, sample-distance, or wavelength on `Exposure`/`Experiment`/`Trace` (`api.ts` — `Trace` is `{ q, I, sigma }`). The detector image is a server-rendered PNG with no q-calibration metadata sent to the client. Therefore the ring overlay uses a **normalized, relative q→radius map** exactly like the mockup `focus-workspace.html` (`renderDetector`: `rr = 12 + (q - qLo)/(qHi - qLo) * 33` over a `100×100` viewBox, beamstop-offset). `qLo`/`qHi` are the min/max of the peak q-set (fallback: the trace q-range). Rings are **presentational** — relative radii proportional to q, centered on the image center — not physically projected. This matches the read-only nature of the panel and the mockup. (Flagged as open decision 1.)
5. **`QNumInput` focus-gate** (PlotCard.tsx ~L524): the q-min/q-max inputs sync the external `value` into their draft **only when not focused** (`useEffect(() => { if (!focused) setDraft(value.toFixed(3)); }, [value, focused])`). The q-link must not feed `hoveredQ` into any `QNumInput` `value`. It doesn't — `hoveredQ` drives *highlight* state (ring/peak stroke), never an input's `value`. The non-interference is structural (separate data paths), and a test asserts a focused `QNumInput` is untouched while `hoveredQ` changes.
6. **JSDOM viewport is 1024px wide by default** (< `ROTATE_MIN_VIEWPORT`), so unit tests render the **portrait** (non-rotated) overlay by default. The landscape/rotation-aware path needs a test that sets `window.innerWidth = 1600` and triggers a resize. `test/setup.ts` already stubs `ResizeObserver` globally (no per-test stub needed).
7. **I4.2 surfaces** (already on main): `FocusWorkspaceLayout` renders `<PlotCard/>` (which renders `<TraceViewer/>`), `<FocusDetectorPanel/>` (which renders `<DetectorImage/>` in an `aspect-square` box), `<IndicesCard/>`, `<FocusNotesMargin/>`. The ring overlay lives inside `FocusDetectorPanel`, layered over its `DetectorImage`. `PlotCard` is the bridge that passes `onHoverQ` to `TraceViewer` and reads `hoveredQ` back for the peak highlight.

```ts
// Shared detector orient-decision — used by DetectorImage (the image canvas)
// and DetectorRingOverlay (the q-link rings), so the ring overlay rotates in
// lockstep with the image instead of re-deriving the rule (#180).

/** Rotate when the container is meaningfully wider than the image's aspect. */
export const ROTATE_THRESHOLD = 1.25;
/** Auto-rotate is gated to viewports >= this width (matches WorkspaceGrid). */
export const ROTATE_MIN_VIEWPORT = 1400;

export interface OrientInput {
  containerW: number;
  containerH: number;
  imageW: number;
  imageH: number;
  viewportW: number;
}
export interface OrientResult {
  orient: "portrait" | "landscape";
  /** Pre-rotation caps (px). Null in portrait. */
  caps: { maxW: number; maxH: number } | null;
}

export function decideOrient(i: OrientInput): OrientResult {
  const { containerW, containerH, imageW, imageH, viewportW } = i;
  if (!containerW || !containerH || !imageW || !imageH) {
    return { orient: "portrait", caps: null };
  }
  if (viewportW < ROTATE_MIN_VIEWPORT) {
    return { orient: "portrait", caps: null };
  }
  const containerAspect = containerW / containerH;
  const imageAspect = imageW / imageH;
  if (containerAspect > imageAspect * ROTATE_THRESHOLD) {
    // Pre-rotation max-width is capped by container HEIGHT (becomes visual
    // height after the 90° rotation), and max-height by container WIDTH.
    return { orient: "landscape", caps: { maxW: containerH, maxH: containerW } };
  }
  return { orient: "portrait", caps: null };
}
```

```ts
// Normalized q -> ring-radius map for the focus-workspace detector overlay.
//
// There is NO detector geometry in the data model (no beam center, pixel size,
// sample distance, or wavelength reach the client — the detector image is a
// pre-rendered PNG). So the rings are PRESENTATIONAL: radius proportional to q
// over the peak q-range, exactly like the mockup `focus-workspace.html`'s
// `renderDetector`. They convey "this peak is this far out", not a calibrated
// projection. (#180 open decision 1.)

/** SVG viewBox edge — the overlay draws in a 100x100 space, centered (50,50). */
export const RING_VIEWBOX = 100;
/** Innermost ring radius (clears the beamstop), mockup parity. */
export const RING_R_MIN = 12;
/** Radial span from qLo..qHi, mockup parity (12..45). */
export const RING_R_SPAN = 33;

/** Map a q-value to a normalized ring radius in the 100x100 viewBox. */
export function qToRadius(q: number, qLo: number, qHi: number): number {
  if (qHi <= qLo) return RING_R_MIN;
  const t = (q - qLo) / (qHi - qLo);
  return RING_R_MIN + t * RING_R_SPAN;
}

/** The peak q nearest `hoveredQ` within `tol`, else undefined (match-highlight). */
export function nearestRingQ(
  hoveredQ: number | undefined,
  peakQs: number[],
  tol: number,
): number | undefined {
  if (hoveredQ === undefined) return undefined;
  let best: number | undefined;
  let bestD = Infinity;
  for (const q of peakQs) {
    const d = Math.abs(q - hoveredQ);
    if (d <= tol && d < bestD) { best = q; bestD = d; }
  }
  return best;
}
```

- [ ] **Step 3: Create the overlay**

> **Rotation approach.** The overlay is an absolutely-positioned SVG filling the same square box as the `DetectorImage` canvas. It accepts an `orient` prop (so the parent — which owns a `ResizeObserver` — can drive it) AND falls back to computing its own orient via `decideOrient` from a `ResizeObserver` on its own wrapper when `orient` is not supplied. Tests pass `orient` explicitly for determinism; in production `FocusDetectorPanel` passes the orient it observes (Task 5) so image and rings rotate together. The SVG uses a `0 0 100 100` viewBox (matching `qRing`), so rings are resolution-independent; the `rotate(90deg)` is applied to the SVG element in landscape, mirroring the canvas.

Create `src/components/DetectorRingOverlay.tsx`:

```tsx
import { useEffect, useRef, useState, type CSSProperties } from "react";
import { useAppState } from "../state";
import { decideOrient } from "../lib/detectorOrient";
import { qToRadius, nearestRingQ, RING_VIEWBOX } from "../lib/qRing";

interface Props {
  /** The peak q-values to draw as rings. */
  peakQs: number[];
  /** Orientation, when the parent drives it (mirrors DetectorImage). When
   *  omitted the overlay self-observes its wrapper. */
  orient?: "portrait" | "landscape";
  /** Pixel tolerance (in q) for matching hoveredQ to a ring. */
  matchTol?: number;
}

const CENTER = RING_VIEWBOX / 2;

/**
 * DetectorRingOverlay — the q-link ring layer over FocusDetectorPanel's
 * detector image (#180). One ring per peak q, positioned by the normalized
 * `qToRadius` map (no detector geometry exists — rings are presentational).
 *
 * Rotation-aware: in landscape the overlay applies the same `rotate(90deg)`
 * as DetectorImage's canvas, via the shared `decideOrient` rule, so rings
 * stay registered with the (rotated) image. We do NOT touch DetectorImage's
 * own rotation logic.
 *
 * Hovering a ring sets `hoveredQ`; a ring whose q matches `hoveredQ` lights.
 */
export function DetectorRingOverlay({
  peakQs, orient: orientProp, matchTol,
}: Props): JSX.Element {
  const wrapperRef = useRef<HTMLDivElement>(null);
  const [selfOrient, setSelfOrient] =
    useState<"portrait" | "landscape">("portrait");
  const orient = orientProp ?? selfOrient;

  const hoveredQ = useAppState((s) => s.hoveredQ);
  const setHoveredQ = useAppState((s) => s.setHoveredQ);

  // Self-observe only when the parent doesn't drive orient.
  useEffect(() => {
    if (orientProp !== undefined) return;
    const wrapper = wrapperRef.current;
    if (!wrapper) return;
    const recompute = (): void => {
      const r = decideOrient({
        containerW: wrapper.clientWidth,
        containerH: wrapper.clientHeight,
        // square overlay → image aspect is 1; rings sit on the image center
        imageW: 1, imageH: 1,
        viewportW: typeof window !== "undefined" ? window.innerWidth : 0,
      });
      setSelfOrient(r.orient);
    };
    recompute();
    const ro = new ResizeObserver(recompute);
    ro.observe(wrapper);
    return () => ro.disconnect();
  }, [orientProp]);

  const qLo = peakQs.length ? Math.min(...peakQs) : 0;
  const qHi = peakQs.length ? Math.max(...peakQs) : 1;
  const tol = matchTol ?? Math.max((qHi - qLo) * 0.02, 1e-6);
  const matched = nearestRingQ(hoveredQ, peakQs, tol);

  const svgStyle: CSSProperties = {
    position: "absolute",
    inset: 0,
    width: "100%",
    height: "100%",
    pointerEvents: "none", // rings re-enable it individually
    ...(orient === "landscape"
      ? { transform: "rotate(90deg)", transformOrigin: "center" }
      : {}),
  };

  return (
    <div ref={wrapperRef} className="pointer-events-none absolute inset-0">
      <svg
        data-testid="detector-ring-overlay"
        data-orient={orient}
        viewBox={`0 0 ${RING_VIEWBOX} ${RING_VIEWBOX}`}
        style={svgStyle}
        aria-hidden="true"
      >
        {peakQs.map((q) => {
          const r = qToRadius(q, qLo, qHi);
          const hot = matched !== undefined && q === matched;
          return (
            <circle
              key={q}
              data-testid={`detector-ring-${q}`}
              data-hot={hot ? "true" : "false"}
              cx={CENTER}
              cy={CENTER}
              r={r}
              fill="none"
              stroke={hot ? "var(--color-accent)" : "var(--color-fg-dim)"}
              strokeWidth={hot ? 1.6 : 0.8}
              opacity={hot ? 0.95 : 0.5}
              style={{ pointerEvents: "stroke", cursor: "pointer" }}
              onMouseEnter={() => setHoveredQ(q)}
              onMouseLeave={() => setHoveredQ(undefined)}
            />
          );
        })}
      </svg>
    </div>
  );
}
```

## Open decisions for the human (do not block the plan)

1. **Rings are presentational, not geometric.** There is no detector geometry in the data model, so ring radius is a normalized q→radius map (mockup parity), not a calibrated projection. The rings convey relative q ordering and support the hover q-link, but their absolute radii are not physically meaningful. Confirm this is acceptable for I4.3 (a calibrated overlay would need new backend geometry fields — out of scope).
2. **Overlay re-observes orient rather than reading it from `DetectorImage`.** To avoid editing `DetectorImage`'s public surface, `DetectorRingOverlay` self-observes its wrapper with the shared `decideOrient`. In the `aspect-square` focus box the detector is normally portrait, so image/rings agree; if we ever need pixel-exact rotation lockstep, threading the exact orient out of `DetectorImage` (a new callback prop) would be tighter but more invasive. Confirm re-observe is acceptable for I4.3.
3. **q-source = trace cursor (peak-snapped) + detector rings.** The acceptance lists "trace peak / detector ring / reflection row." The focus workspace's rail (`IndicesCard`/`PhasePanel`) hovers at the *index* level (`hoveredIndexId`), not per-peak-q; there is no standalone per-peak "reflection row" component today. I4.3 wires the two q-bearing surfaces (trace peaks ↔ detector rings) and the trace's own peak highlight; the rail's index hover stays on its existing channel. If the human wants the rail rows to also drive `hoveredQ`, that needs a per-peak row source in PhasePanel (a small follow-up). Confirm trace↔detector is sufficient for I4.3's "lights all three" (trace peak, detector ring, and the trace peak-highlight responding to ring hover = three lit surfaces), or scope in the rail row.
4. **TraceViewer gains optional props (a reused component touched).** Unlike I4.2 (pure composition), I4.3 necessarily edits `TraceViewer` (the only q-source) and `DetectorImage` (orient extraction). Both edits are additive/behavior-preserving and guarded by the unchanged regression-floor suites. Confirm this is the intended reading of "compose on top of" (the issue explicitly scopes a rotation-aware overlay + a hover channel, which cannot be done without a source seam).
