# M-E — Corpus shell reskin (onto the print design system)

> Finish-line milestone M-E. Recompose the carried app-shell topbar from the already-built greenfield `src/print/ui/` primitives, preserving every behavior + testid contract. Presentation-only; no behavior change.

**Goal:** The live shell (`CorpusShell`/`CorpusTopbar`) joins the closed-look print design system — composing `src/print/ui/TopBar` + `Wordmark` + print `SegmentedControl`/`IconButton`/`Kicker` — instead of hand-rolling inline appearance utilities and importing the OLD `src/components/ui/` barrel. The shell already uses greenfield *tokens* and renders correctly; this is a design-system-coherence reskin, verified to render identical-or-better.

**Architecture:** `CorpusShell` (in `src/components/`) stays the layout route (already token-clean: `bg-paper text-ink`, thin). `CorpusTopbar` is rebuilt to compose the print `TopBar` slot-shell (`wordmark` / `children` / `rightSlot`). All routing/query/stepper LOGIC is reused verbatim (no-legacy-port = reuse logic, rebuild presentation). The component files remain in `src/components/` (they are the carried shell, not `src/print/**` pages — moving them is out of scope; only their PRESENTATION swaps to print primitives).

## Hard contract — MUST preserve (tests + e2e assert these)
- **Testids (exact, on the same semantic elements):** `corpus-shell`, `corpus-topbar`, `corpus-wordmark`, `stage-tabs`, `stage-tab-samples`, `stage-tab-series`, `beamtime-chip`, `sample-stepper`, `sample-stepper-prev`, `sample-stepper-next`. (Note: `print/ui/TopBar` uses `data-testid="topbar"` and `Wordmark` uses `data-testid="wordmark"` — the reskinned `CorpusTopbar` must still expose `corpus-topbar`/`corpus-wordmark`; pass them through via the primitives' `className`-only API won't carry a testid, so either wrap or extend. Simplest: keep the print `TopBar` for layout/appearance but ensure the OUTER element carries `data-testid="corpus-topbar"` — e.g. pass a `data-testid` through, or wrap. Check `TopBar`'s props: it only takes `className`; add a `data-testid`/`...rest` passthrough to `TopBar` (a print-ui primitive change is allowed — it's additive and in the design-system dir) OR render the `corpus-topbar` testid on the `Wordmark`'s parent. Prefer extending `TopBar` with an optional `data-testid` prop — minimal, reusable.)
- **Behavior:** active-tab derivation (`pathname.startsWith(stage.to)` → `data-active`/`aria-current`), the accent leading-dot on each tab, beamtime `?beamtime=` URL read/write (only shown on `/samples`), the focus-route sample stepper (prev/next nav, `sample N of M`, gated on `/sample/:id` + active sample), the wordmark link to `/samples` with its aria-label.
- **Design guard:** `npm run lint:design` must stay 0. The reskin REMOVES hand-rolled appearance (the `tracking-[0.16em]` etc. move into `Wordmark`, which already owns them); do not introduce new inline appearance utilities outside `print/ui`. The stage-tab pill / beamtime chip / stepper appearance should come from print primitives (`SegmentedControl` for the tabs is the natural fit if it supports link items; if not, keep the tabs as `Link`s styled via a small print-ui tab primitive or `Kicker`/`Button ghost` — judgment call, but appearance must live in `print/ui`, placement-only className at the call site).
