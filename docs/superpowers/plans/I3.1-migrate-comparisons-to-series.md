# I3.1 — `migrate_comparisons_to_series!` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Event-source-copy every existing `comparisons` row (plus its messages and pins) into the `series*` tables at `migrate_schema!` time, by synthesizing `series_created` + `series_plate_committed` `user_actions` rows and folding them through the existing pure-replace dispatcher branches — idempotent, sentinel-gated, no SSE broadcast.

**Architecture:** A new `migrate_comparisons_to_series!(db)` in `db.jl`, spliced into the `migrate_schema!` sequence body **after** `migrate_compare_view_choices!` and immediately after `migrate_series!` (which creates the `series*` tables + the `schema_migrations` sentinel). The function opens its own `SQLite.transaction`, gates on a `schema_migrations` marker row, and for each comparison: (1) builds a `series_created` payload (recipe snapshot derived from the comparison's members' samples; zero members) and a `series_plate_committed` payload (the full member list, ids stripped); (2) raw-`INSERT`s two `user_actions` rows (`entity_type='series'`, `client_op_id`/`client_id` NULL, `user_id` + historical `timestamp` carried from the comparison); (3) folds each payload through `update_view_for_event!` exactly as live replay does — so the log and the view rows agree by construction; (4) copies `comparison_messages`→`series_messages` and `comparison_pins`→`series_pins`; (5) writes the sentinel marker row **last, inside the same transaction**. Because `apply_event!` is never called, no broadcast fans out and no `idempotent_responses` rows are written.

**Tech Stack:** Julia, SQLite.jl / DBInterface, JSON3, stdlib `Test`. All code lives in `packages/HimalayaUI/src/db.jl`; tests in `packages/HimalayaUI/test/test_migrate_comparisons_to_series.jl` (new) registered in `runtests.jl`.

### Exact existing shapes the implementer depends on (do not re-derive)

**`migrate_schema!` sequence body** (`db.jl`, current `main` line numbers; verify after rebase):
```
migrate_compare!(db)                       # ~354
migrate_comparison_pins!(db)               # ~357
migrate_compare_relax_nullability!(db)     # ~364
migrate_compare_view_choices!(db)          # ~368
migrate_series!(db)                        # ~375  (creates series* + schema_migrations, all empty)
migrate_experiment_config_label_to_name!(db)  # ~385
```
**Insertion point:** a new `migrate_comparisons_to_series!(db)` call goes **immediately after `migrate_series!(db)`** (so the `series*` tables and the `schema_migrations` sentinel table exist) and after the two named compare migrations (so the relaxed-nullability + view-choice columns are present on `comparisons`). It is `migrate_schema!`'s job to call it; `migrate_schema!` is itself NOT wrapped in an outer transaction by `open_db` (`open_db` is `create_schema!` then `migrate_schema!`, no surrounding tx), so the migration opening its own `SQLite.transaction` is correct and self-contained.

**`series_created` payload shape** the dispatcher (`_update_view_for_series_created!`, `events.jl:757`) reads — must match the route's POST payload (`routes_series.jl:139-150`):
```
Dict{Symbol,Any}(
  :title, :description, :forked_from_id, :forked_at_hash,
  :ordering_variable, :order_rule,
  :view_grouping_mode, :view_show_peak_ticks, :view_show_peak_labels,
  :samples => [ Dict(:sample_id, :position, :pinned, :excluded), ... ],   # recipe snapshot
)
```
The dispatcher sets `state='draft'`, leaves `content_hash` NULL, derives `created_by` from the event row via `user_id_for_event(db, event_id)`, and **stamps `created_at`/`updated_at` with `comparison_now_iso()` (migration wall-clock time), NOT the comparison's historical `created_at`** (`events.jl:760,791,810` — the dispatcher hardcodes `now_str`). This is a deliberate consequence of folding through the live dispatcher: the *event row* carries the historical `timestamp` (so the audit log / `last_event_at` sort is faithful), but the *series view row's* `created_at` is migration-time. Tests must NOT assert the migrated series' `created_at` equals the comparison's `created_at`. **`order_rule` is `COALESCE`'d to `'manual'`** by the dispatcher when the payload value is NULL, satisfying the `CHECK (order_rule IN ('ascending','descending','manual'))`.

**`series_plate_committed` payload shape** the dispatcher (`_update_view_for_series_plate_committed!`, `events.jl:905`) reads — must match the route's commit payload (`routes_series.jl:248`):
```
Dict{Symbol,Any}(:members => [ <member>, ... ])
```
where each `<member>` matches `_series_member_payload` output (`series.jl:357`):
```
Dict(:id=>nothing, :exposure_id, :display_order, :band_height, :y_offset,
     :normalization, :color_override, :label_override,
     :q_window_min, :q_window_max, :peak_display, :snapshot)
```
The dispatcher `DELETE`s `series_members` by `series_id`, INSERTs each member (minting fresh PKs — members carry `:id=>nothing`), then sets `state='committed'` and `content_hash = compute_series_content_hash(db, sid)`.

**`comparison_members` columns** (source of the plate): `id, comparison_id, exposure_id, display_order, band_height, y_offset, normalization, color_override, label_override, q_window_min, q_window_max, peak_display, snapshot, created_by, created_at`. `snapshot` is `NOT NULL CHECK(json_valid)`; `peak_display` is nullable JSON. **Reuse `fetch_comparison_with_members(db, cid)`** (`comparisons.jl:398`) to get the comparison + parsed members in one call — its member Dicts already have the right field names, except `:id`/`:comparison_id`/`:is_stale`/`:created_by`/`:created_at` which the plate payload must drop or ignore.

**Recipe derivation (the one genuinely new mapping).** A comparison has no recipe; the `series_created` `samples` snapshot is "derived from the comparison's members' samples" (§6.1 step 2). `exposures.sample_id` references `samples(id)` and is **nullable**. So: for each comparison member in `display_order` order, look up `exposures.sample_id` for the member's `exposure_id`; collect the **distinct, non-NULL** sample ids preserving first-seen order; emit one recipe entry per distinct sample with sequential 0-based `position`, `pinned=false`, `excluded=false`. Members with NULL `exposure_id` (orphans) or whose exposure has NULL `sample_id` contribute no recipe row. A comparison whose members yield zero sample ids gets an empty `samples` snapshot (valid — a draft with an empty recipe).

**Sentinel marker.** `schema_migrations(name TEXT PRIMARY KEY, applied_at TEXT)`. Use a single stable marker name constant, e.g. `const MIGRATION_COMPARISONS_TO_SERIES = "comparisons_to_series"`. Gate: `SELECT 1 FROM schema_migrations WHERE name = ?` — present ⇒ skip. Write `INSERT INTO schema_migrations (name, applied_at) VALUES (?, ?)` as the **final statement before the transaction's implicit commit**, with `applied_at = comparison_now_iso()`.

**Raw user_actions INSERT.** Match the column list `apply_event!(InTransaction)` uses (`events.jl:124-128`) but with the migration-specific values. **CRITICAL: the timestamp column on `user_actions` is named `timestamp`, NOT `created_at`** (`db.jl:147-159` SCHEMA: `timestamp DATETIME DEFAULT CURRENT_TIMESTAMP`). Referencing `created_at` would throw `no such column`. `apply_event!(InTransaction)` itself does **not** write the timestamp column at all — it relies on the `DEFAULT CURRENT_TIMESTAMP` (its INSERT column list is `(user_id, action, entity_type, entity_id, payload, undoes_event_id, client_id, client_op_id)`). The migration carries the comparison's original timestamp into the `timestamp` column (§6.1 step 3 "carrying … created_at"):
```
INSERT INTO user_actions
  (user_id, action, entity_type, entity_id, payload, undoes_event_id, client_id, client_op_id, timestamp)
VALUES (?, ?, 'series', ?, ?, NULL, NULL, NULL, ?)
```
- `user_id` = comparison's `created_by` (NULL-safe; comparison `created_by` is `SET NULL` so may be missing). **This is the load-bearing carry**: the `series_created`/`series_plate_committed` dispatcher derives the series row's `created_by` via `user_id_for_event(db, event_id)`, which reads `user_actions.user_id`. Carrying it is what makes the migrated series attributed to the original author.
- `action` = `"series_created"` / `"series_plate_committed"`.
- `entity_id` = the new series id (same id for both rows).
- `payload` = `JSON3.write(payload_dict)`.
- `timestamp` = comparison's `created_at` (carry the original timestamp; §6.1 step 3).

**The series id problem.** The live route mints the series id with `INSERT INTO series DEFAULT VALUES` then the dispatcher UPDATEs that row. The migration must do the **same**: `INSERT INTO series DEFAULT VALUES` → capture `lastrowid` as `new_id` → use `new_id` as the `entity_id` for both synthesized events → fold. The `series_created` dispatcher's live-path branch (`SELECT id ... → UPDATE`) then updates the placeholder; this is exactly the live route path, so the fold behaves identically. (Do **not** try to reuse the comparison's id as the series id — `series.id` is its own AUTOINCREMENT space and the round-trip test must not assume id equality.)

**Fold call.** After raw-INSERTing each `user_actions` row and capturing its `event_id = lastrowid`, call:
```julia
payload_canonical = JSON3.read(JSON3.write(payload_dict))   # canonicalize, matching apply_event!
update_view_for_event!(db, kind, new_id, payload_canonical, event_id)
```
The JSON3 round-trip is mandatory: the live path canonicalizes the payload before dispatch (`events.jl:159-161`), and the dispatcher branches index fields via `payload.field` on a `JSON3.Object`. Passing a raw `Dict` would change key-access semantics and the `haskey` guards.

**Messages / pins copy.** Per comparison, after the series row exists:
```
INSERT INTO series_messages (series_id, author_id, body, created_at)
  SELECT <new_id>, author_id, body, created_at FROM comparison_messages WHERE comparison_id = ?
INSERT INTO series_pins (user_id, series_id, pinned_at)
  SELECT user_id, <new_id>, pinned_at FROM comparison_pins WHERE comparison_id = ?
```
Carry `created_at`/`pinned_at` explicitly (don't let the `DEFAULT CURRENT_TIMESTAMP` overwrite history). `series_messages.id` is its own PK space — let it auto-assign. `series_pins` PK is `(user_id, series_id)`; a comparison pinned twice by the same user can't happen (comparison_pins PK is `(user_id, comparison_id)`), so no `OR IGNORE` needed, but using `INSERT OR IGNORE` is harmless defense and recommended.

**Ordering / determinism.** Iterate comparisons `ORDER BY id ASC` so synthesized `user_actions` ids append in a stable order. Within a comparison, emit `series_created` before `series_plate_committed` (the dispatcher's recipe-update assumes create folded first; the commit reads the just-created row).

```julia
"""
    migrate_comparisons_to_series!(db)

Event-sourced copy of every `comparisons` row into the `series*` tables
(master plan §6.1, issue #171). Runs at `migrate_schema!` time, after
`migrate_series!` (so the `series*` tables and `schema_migrations` sentinel
exist) and after `migrate_compare_view_choices!`/`migrate_compare_relax_nullability!`
(it reads the columns those add). Wrapped in its own `SQLite.transaction`.

Idempotent via the `schema_migrations` sentinel (gate at start, marker row
written LAST inside the same transaction — the gate flips only on a fully
committed copy). NEVER calls `apply_event!` (its public method broadcasts; a
migration must not fan out N replay-as-reruns). Raw-`INSERT`s `user_actions`
rows with `client_op_id`/`client_id` NULL — so no `idempotent_responses` cache
rows are written and the partial unique index does not apply.
"""
function migrate_comparisons_to_series!(db::SQLite.DB)
    # Gate: skip if already applied. A single read before the transaction is
    # sufficient — migrate_schema! runs single-threaded inside open_db, before
    # serve accepts connections, so there is no concurrent opener to race.
    already = Tables.rowtable(DBInterface.execute(db,
        "SELECT 1 FROM schema_migrations WHERE name = ?",
        [MIGRATION_COMPARISONS_TO_SERIES]))
    isempty(already) || return nothing

    SQLite.transaction(db) do
        # (Task 2 fills in the per-comparison copy loop here.)

        # Sentinel marker LAST, inside the same transaction.
        DBInterface.execute(db,
            "INSERT INTO schema_migrations (name, applied_at) VALUES (?, ?)",
            [MIGRATION_COMPARISONS_TO_SERIES, comparison_now_iso()])
    end
    nothing
end
```

            VALUES (1, 'Cmp A', 'desc', 'oldhash', 5, '2026-01-01T00:00:00.000Z',

        # set them EXPLICITLY here so a future schema change that drops the

            VALUES (1, 100, 0, 1.0, 0.0, 'none', ?, '2026-01-01T00:00:00.000Z'),

            [MIGRATION_COMPARISONS_TO_SERIES])

            "SELECT id, title, description, state, content_hash, created_by, created_at FROM series"))

        # dispatcher stamps the series row's created_at with comparison_now_iso()
        # (migration time). The HISTORICAL timestamp lives on the event row's
        # `timestamp` column (asserted below), not the series view row.

        sid = Int(s.id)

        # Two members, ids minted fresh, display_order preserved.
        mrows = Tables.rowtable(DBInterface.execute(db,
            "SELECT exposure_id, display_order FROM series_members WHERE series_id = ? ORDER BY display_order", [sid]))
        @test length(mrows) == 2
        @test Int(mrows[1].exposure_id) == 100
        @test Int(mrows[2].exposure_id) == 101

           FROM comparison_members cm
           JOIN exposures e ON e.id = cm.exposure_id
           WHERE cm.comparison_id = ? AND e.sample_id IS NOT NULL
           ORDER BY cm.display_order ASC, cm.id ASC""", [Int(cmp.id)]))

    samples = Vector{Dict{Symbol,Any}}()
    for r in sample_rows
        sid = Int(r.sample_id)
        sid in seen && continue
        push!(seen, sid)
        push!(samples, Dict{Symbol,Any}(

function _synthesize_series_event!(db::SQLite.DB, kind::String, series_id::Integer,
                                   payload::Dict, user_id, ts)

              undoes_event_id, client_id, client_op_id, timestamp)

## Open risks / decisions for the reviewers and the human

1. **Sentinel-gate timing vs. real cutover.** On a fresh empty DB, `migrate_schema!` runs `migrate_series!` (writes the sentinel table empty) then `migrate_comparisons_to_series!` (sees zero comparisons, writes the sentinel marker). On a **populated** comparison-era DB the marker is absent, so the first `open_db` after deploy does the real copy. **But:** a DB that was opened once while still empty (marker written) and then somehow gained comparisons without the marker being cleared would skip the copy. In practice comparisons only arrive via the route, which never ran on an empty-then-served DB before this PR ships — but the tests must (and do, Task 2/3/4/5) clear the marker to simulate "comparisons present, not yet migrated." **Decision for the human:** is the empty-DB-writes-the-marker behavior acceptable, or should the gate only write the marker when it actually copied ≥0 comparisons on a DB that *had* a comparisons table with rows at some point? The plan's current stance: write the marker unconditionally once the migration runs to completion (matches §6.1 step 5 "after the loop"); the empty case is genuinely "migrated (nothing to do)."
2. **`user_actions` timestamp column (RESOLVED — was a latent bug in draft v1).** The `user_actions` timestamp column is named **`timestamp`**, not `created_at` (`db.jl:150`). The plan now writes the carried historical timestamp into `timestamp`. The live `apply_event!(InTransaction)` path does NOT set the timestamp at all (relies on `DEFAULT CURRENT_TIMESTAMP`); carrying it explicitly here is the spec requirement (§6.1 step 3) and a deliberate, harmless divergence (no trigger/generated-column on that table). The *series view row's* `created_at` is migration wall-clock (dispatcher-stamped), not the comparison's — see the "series id problem" / dispatcher note above; tests assert the historical timestamp on the event row, not the series row.
3. **`compute_series_content_hash` parity with comparisons.** The migrated series' `content_hash` is computed fresh by the `series_plate_committed` dispatcher from the series plate; it will NOT equal the old `comparisons.content_hash` (different hash domain). The round-trip test asserts before==after within the series domain, not cross-domain equality. Confirmed intentional.
4. **`view_show_peak_ticks`/`labels` type round-trip.** These are stored as INTEGER (0/1/NULL) on `comparisons`; the payload passes the raw value and the dispatcher writes it back. No Bool coercion needed in the migration (the dispatcher does a bare write). Flagged in case a reviewer wants explicit 0/1 normalization.
5. **Out of scope (confirm):** no frontend, no new event kind, no route changes, no `comparison*` table/branch deletion (that is the end-of-phase cutover, a separate issue). The six-layer obligation is met by the existing #166/#167 per-kind tests + this plan's migrated-row round-trip.
6. **Fork lineage dropped on migration (FIX applied — himalaya-reviewer P1; HUMAN SIGN-OFF REQUESTED).** `comparisons.forked_from_id` (references `comparisons(id)`) and `series.forked_from_id` (references `series(id)`) live in **different id-spaces**. Copying the comparison's id straight through would write a dangling reference that inserts silently (migrate_schema! runs FK-off; `PRAGMA foreign_keys=ON` is enabled by `open_db` *after* the migration — db.jl:1583 then 1590) and would later surface via `PRAGMA foreign_key_check` or any fork-tree read. A comparison_id→series_id remap is unsafe because id-order does not guarantee parent.id < child.id. **Decision taken (reviewer-recommended option a):** NULL both `forked_from_id` and `forked_at_hash` on every migrated series — fork lineage across the comparison→series cutover is not meaningful. Task 5 has a regression test (`PRAGMA foreign_key_check(series)` clean). **If the human believes fork lineage MUST survive the cutover**, this is the one decision to revisit — it would require a two-pass migration (pass 1 mint all series ids + a comparison_id→series_id map; pass 2 backfill `forked_from_id` from the map) and is a larger change. Default stance: null it.
