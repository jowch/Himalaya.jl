# I4.2 — Focus-workspace layout — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the `FocusWorkspacePage` placeholder (shipped in I4.1) with the real focus-workspace layout at `/sample/:sampleId` — trace as the hero plate, a co-resident read-only detector image, the phase call + candidate indexings as a rail, and the sample's Notes as a margin/drawer — by **composing existing, unchanged components** so indexing one sample works exactly as it does on the legacy `/index` surface.

**Architecture:** A pure-composition page. The trace hero is the existing `<PlotCard />` verbatim (it already wraps TraceViewer + scale/auto-fit/export controls + legend, and it is the component that drives `useAutoPickExposure` — see *Load-bearing facts*). The rail is the existing `<IndicesCard />` verbatim (PhasePanel = phase call + candidates, plus the MillerPlot √N sanity inset). The co-resident detector is the existing `<DetectorImage size="full">` of the active exposure, wrapped in a thin read-only `FocusDetectorPanel` (the q-link hover interactivity is I4.3, out of scope here). Notes is a thin `FocusNotesMargin` reading/writing `sample.notes` via the existing `useUpdateSample` mutation with the established focus-gate. The layout is a CSS grid mirroring the mockup `docs/redesign-mockups/focus-workspace.html`: `[ work | rail | notes ]`, with the notes margin collapsing below a breakpoint. **No reused component's behavior or props change.**

**Tech Stack:** React 18, react-router-dom v6, Zustand (`useAppState`), TanStack Query, boneyard-js Skeleton, Tailwind v4 (`@theme` tokens), Vitest + RTL + `MemoryRouter`.

## Load-bearing facts the implementer must know

1. **`useAutoPickExposure` lives inside `PlotCard`** (`PlotCard.tsx:102`, `useAutoPickExposure(activeSampleId)`). It is a render side-effect: mounting `<PlotCard/>` is what seeds `activeExposureId` from the sample's representative/first-accepted exposure. **Consequences:**
   - The focus page MUST render exactly **one** `<PlotCard/>`. Mounting it twice would run the auto-pick effect twice (harmless idempotent in practice, but a smell) — render it once.
   - The detector panel and rail read `activeExposureId` from Zustand, which `PlotCard` populates. So `<PlotCard/>` must be mounted in the tree alongside them (it is — they are siblings under the page). There is no ordering hazard: all three are Zustand subscribers; when `PlotCard`'s effect sets `activeExposureId`, the detector/rail re-render.
   - Do NOT add a second `useAutoPickExposure` call in the page — that would duplicate the effect. The single source remains PlotCard.
2. **The I4.1 shim is already mounted.** `FocusWorkspacePage` calls `useSyncActiveSampleFromRoute()` (URL `:sampleId` → `activeSampleId`). Keep that call; the layout renders below it.
3. **`activeSampleId` → `activeExposureId` chain:** shim sets `activeSampleId` (from URL); `PlotCard`'s `useAutoPickExposure` sets `activeExposureId`; detector + rail consume both. This is the same chain the legacy IndexPage uses — we are only re-arranging the boxes.
4. **DetectorImage props** (`components/DetectorImage.tsx`): `{ exposureId: number; imagePath: string | null; imageVersion: string; size: "thumb" | "full"; className?: string }`. The active `Exposure` object (from `useExposures(activeSampleId)`) carries `image_path` and `image_version`. Render read-only — no status/reject/tag controls (those are Inspect's `DetectorImageCard`, deliberately NOT reused here; the mockup's detector panel is read-only).
5. **`DetectorImage` auto-rotate is gated to viewport ≥ 1400px and keyed off a ResizeObserver** (`ROTATE_MIN_VIEWPORT`). The mockup's detector lives in a fixed-aspect square (`--det-size`). Wrap it in an `aspect-square` container as `LoupeFrame` does — do not fight the rotation logic; just give it a square box (components/AGENTS.md: CSS-only rotate doesn't work, the component manages its own box via JS).
6. **Notes — read-source MUST equal write-target (cache coherence).** `Sample.notes: string | null`. Write via `useUpdateSample(experimentId, sampleId)` → `.mutate({ notes })`. **The notes textarea must read its `sample` from the experiment-scoped `useSamples(experimentId)` query — NOT from `useCorpusSamples`.** Reason: `updateSampleMutator` (`lib/queue/mutators/trivial.ts`) optimistically patches `queryKeys.samples(experimentId)` + `queryKeys.sample(sampleId)` and never touches `queryKeys.corpusSamples` (`["corpus","samples"]`); `useQueueMutation` does no broad corpus invalidation. If the textarea read off the corpus cache, the on-blur focus-gate would re-sync the *stale* corpus value and silently revert the user's edit. This is exactly the proven Inspect path: `InspectPage` sources its sample from `useSamples(experimentId).data?.find(...)` (InspectPage.tsx:125,127) and writes via `useUpdateSample(experimentId, sampleId)` (161) — read-source == write-target. We learn `experimentId` from the corpus sample's authoritative `experiment_id` (the shim seeds only `activeSampleId`). Mirror the **focus-gate** from `SampleMetadataCard`/`QNumInput`: sync external `sample.notes` into the draft only when the textarea is **not** focused. We do NOT reuse `SampleMetadataCard` (bundles name/tags/exposure-summary editing); a thin `FocusNotesMargin` is the right grain. **We do NOT add corpus-cache patching to `updateSampleMutator`** — that shared mutator stays untouched (it would break pure-composition scope and the regression floor).
7. **Tailwind tokens (verified in `styles.css`):** the corpus light-aesthetic tokens `--color-paper`, `--color-paper-sunk`, `--color-plate`, `--color-ink`, `--color-ink-soft`, `--color-ink-faint`, `--color-hair`, `--color-hair-strong` all exist (lines 31–38), so `bg-paper`, `bg-paper-sunk`, `bg-plate`, `text-ink`, `text-ink-soft`, `text-ink-faint`, `border-hair`, `border-hair-strong` are valid utilities. The detector frame uses the older `border-border` / `bg-bg` tokens that `LoupeFrame` uses (also present). There is **no** `.panel` class and **no** `frame-edge` token — do not reference them. Do NOT hardcode the mockup's raw `oklch(...)` values in components (components/AGENTS.md: new colors go in `@theme` first); if a needed token is genuinely missing, add it to `@theme` in its own step.
8. **Boneyard skeletons:** `PlotCard` and `PhasePanel` already own their own `<Skeleton>` fixtures internally — composing them carries those skeletons for free. The two NEW panels (`FocusDetectorPanel`, `FocusNotesMargin`) need their own loading treatment: a `<Skeleton>` or a simple `HintText` fallback while `useExposures` / corpus data is loading. Acceptance requires "boneyard skeletons cover the data-driven panels" — the detector panel is data-driven (needs the exposure), so give it a Skeleton; Notes can use a quiet fallback (it is a margin, not a card).
9. **`HintText` import (verified):** `HintText` is re-exported from the `./ui` barrel (`components/ui/index.ts:4` → `export { HintText } from "./HintText"`), so `import { HintText } from "./ui"` resolves. No need to import `./ui/HintText` directly.

import { Skeleton } from "boneyard-js/react";
import { useAppState } from "../state";
import { useExposures } from "../queries";
import { DetectorImage } from "./DetectorImage";
import { HintText } from "./ui";

/**
 * FocusDetectorPanel — the co-resident detector image on the focus workspace.
 *
 * Read-only: it shows the active exposure's diffraction image next to the
 * trace hero, in a fixed-aspect square (the mockup's `.det-box`). The q-link
 * cross-highlight (hover a peak -> light its ring) is I4.3 (#180), not here.
 *
 * Reuses `DetectorImage` unchanged. We deliberately do NOT reuse the Inspect
 * `DetectorImageCard` — that bundles reject/tag/representative controls; the
 * focus surface's detector is a read-only companion to the trace.
 */
export function FocusDetectorPanel(): JSX.Element {
  const activeSampleId   = useAppState((s) => s.activeSampleId);
  const activeExposureId = useAppState((s) => s.activeExposureId);
  const exposuresQ = useExposures(activeSampleId);

  const exposure = activeExposureId !== undefined
    ? exposuresQ.data?.find((e) => e.id === activeExposureId)
    : undefined;

  const body = (() => {
    if (activeSampleId === undefined) {
      return (
        <div data-testid="focus-detector-empty"
             className="flex-1 flex items-center justify-center">
          <HintText>Pick a sample to see its detector image.</HintText>
        </div>
      );
    }
    if (exposure === undefined || !exposure.image_path) {
      return (
        <div data-testid="focus-detector-empty"
             className="flex-1 flex items-center justify-center">
          <HintText>No detector image for this exposure.</HintText>
        </div>
      );
    }
    return (
      // Frame classes copied from LoupeFrame (the proven detector wrapper):
      // `aspect-square ... overflow-hidden rounded border border-border bg-bg`.
      // DetectorImage owns its own rotation via JS, so we only give it a box.
      <div className="relative mx-auto aspect-square w-full max-w-[420px]
                      overflow-hidden rounded border border-border bg-bg">
        <DetectorImage
          exposureId={exposure.id}
          imagePath={exposure.image_path}
          imageVersion={exposure.image_version}
          size="full"
          className="h-full w-full"
        />
      </div>
    );
  })();

  return (
    // Card chrome mirrors the index cards: a bordered plate surface. `.panel`
    // is NOT an existing utility class — use explicit Tailwind/token classes.
    <section data-testid="focus-detector-panel"
             className="flex min-h-0 flex-col rounded border border-hair
                        bg-plate p-4">
      <div className="card-header">
        <span className="text-meta uppercase tracking-wider">Detector image</span>
      </div>
      <Skeleton
        name="focus-detector"
        className="flex-1 min-h-0 flex flex-col"
        loading={activeExposureId !== undefined && exposuresQ.isLoading}
        stagger={50}
        transition={200}
        fallback={
          <div className="flex-1 flex items-center justify-center">
            <HintText>Loading detector image…</HintText>
          </div>
        }
      >
        {body}
      </Skeleton>
    </section>
  );
}
```

There is **no** `.panel` utility class and **no** `bg-frame-edge` token — do not use them. ```tsx
import { useEffect, useState } from "react";
import type { Sample } from "../api";

interface Props {
  sample: Sample;
  /** Called on blur with the trimmed-or-raw edited notes value. */
  onSaveNotes: (notes: string) => void;
}

/**
 * FocusNotesMargin — the Notes margin on the focus workspace (the mockup's
 * `.notes-margin`: a quiet ruled column, deliberately not a card).
 *
 * Focus-gated edit (mirrors SampleMetadataCard / QNumInput): the external
 * `sample.notes` is synced into the draft only while the textarea is NOT
 * focused, so a background refetch or another user's save can't clobber a
 * mid-edit draft. Switching samples still works because focus moves out
 * before the new sample renders.
 */
export function FocusNotesMargin({ sample, onSaveNotes }: Props): JSX.Element {
  const [draft, setDraft] = useState(sample.notes ?? "");
  const [focused, setFocused] = useState(false);

  useEffect(() => {
    if (!focused) setDraft(sample.notes ?? "");
  }, [sample.id, sample.notes, focused]);

  return (
    <aside data-testid="focus-notes-margin"
           className="flex flex-col gap-2 border-l border-hair bg-paper px-4 py-5">
      <div className="text-meta uppercase tracking-wider text-ink-faint">Notes</div>
      <textarea
        data-testid="focus-notes-input"
        value={draft}
        onChange={(e) => setDraft(e.target.value)}
        onFocus={() => setFocused(true)}
        onBlur={() => {
          setFocused(false);
          onSaveNotes(draft);
        }}
        placeholder="Add a note…"
        className="min-h-[120px] w-full resize-none bg-transparent text-sm
                   text-ink-soft outline-none placeholder:text-ink-faint"
      />
    </aside>
  );
}
```

import { useAppState } from "../state";
import { useCorpusSamples, useSamples, useUpdateSample } from "../queries";
import { PlotCard } from "./PlotCard";
import { IndicesCard } from "./IndicesCard";
import { FocusDetectorPanel } from "./FocusDetectorPanel";
import { FocusNotesMargin } from "./FocusNotesMargin";

/**
 * FocusWorkspaceLayout — the focus-workspace grid (mockup focus-workspace.html):
 *
 *   [ work (trace hero + co-resident detector) | rail (phase call) | notes ]
 *
 * Pure composition. Every panel is an existing component reused unchanged:
 *   - trace hero  = <PlotCard/>      (also drives useAutoPickExposure)
 *   - rail        = <IndicesCard/>   (PhasePanel phase call + candidates + Miller)
 *   - detector    = <FocusDetectorPanel/> (read-only DetectorImage; q-link is I4.3)
 *   - notes       = <FocusNotesMargin/>
 *
 * The notes margin is the first column to yield: it collapses below the
 * `xl` breakpoint (mirrors the mockup's max-width:1320px rule). The q-link
 * cross-highlight (#180) and the Index cutover (#181) are out of scope.
 */
export function FocusWorkspaceLayout(): JSX.Element {
  const activeSampleId = useAppState((s) => s.activeSampleId);

  // The corpus query gives us the sample's authoritative `experiment_id`
  // (the I4.1 route shim seeds only `activeSampleId`, NOT activeExperimentId).
  const corpusQ = useCorpusSamples();
  const corpusSample = activeSampleId !== undefined
    ? corpusQ.data?.find((s) => s.id === activeSampleId)
    : undefined;
  const experimentId = corpusSample?.experiment_id;

  // CACHE-COHERENCE (blocking-review fix): the notes textarea must read from
  // the SAME cache `updateSampleMutator` patches. That mutator writes
  // queryKeys.samples(experimentId) + queryKeys.sample(sampleId) — it does
  // NOT touch queryKeys.corpusSamples. So we source the notes sample from
  // `useSamples(experimentId)` (the experiment-scoped list), exactly as the
  // proven Inspect path does (InspectPage.tsx:125,161 → SampleMetadataCard →
  // useUpdateSample). Reading notes off `useCorpusSamples` instead would make
  // the on-blur focus-gate re-sync a stale value and silently revert the edit.
  const samplesQ = useSamples(experimentId ?? 0);
  const notesSample = activeSampleId !== undefined && experimentId !== undefined
    ? samplesQ.data?.find((s) => s.id === activeSampleId)
    : undefined;

  // Write target uses the authoritative experiment_id (NOT the nullable
  // activeExperimentId, which isn't seeded on /sample/:sampleId). Hook is
  // always called (hooks rule); it only fires from the margin's blur.
  const updateSample = useUpdateSample(experimentId ?? 0, activeSampleId ?? 0);

  return (
    <div
      data-testid="focus-workspace-layout"
      className="grid min-h-0 flex-1 grid-cols-1 xl:grid-cols-[1fr_348px_250px]"
    >
      {/* work area: trace hero stacked over the co-resident detector */}
      <div className="flex min-h-0 flex-col gap-5 overflow-auto p-6">
        <div className="min-h-[420px]">
          <PlotCard />
        </div>
        <FocusDetectorPanel />
      </div>

      {/* rail: the phase call + candidates */}
      <aside className="min-h-0 overflow-y-auto border-l border-hair bg-paper-sunk">
        <IndicesCard />
      </aside>

      {/* notes margin: collapses below xl. Gated on the experiment-scoped
          sample being loaded so the textarea never reads a stale source. */}
      {notesSample !== undefined && (
        <div className="hidden xl:block">
          <FocusNotesMargin
            sample={notesSample}
            onSaveNotes={(notes) => updateSample.mutate({ notes })}
          />
        </div>
      )}
    </div>
  );
}

The detector/rail/trace don't have this problem: they key off `activeExposureId` (seeded by PlotCard's `useAutoPickExposure`) and `activeSampleId`, not off sample *fields*.
