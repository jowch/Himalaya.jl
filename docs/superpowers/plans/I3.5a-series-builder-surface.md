**Goal:** Build the read-only series builder visual surface at `/series/:id` — the consolidated `series-builder.html`: an offset-waterfall trace overlay rendered by composing the existing `MultiTracePlot` render core, a collapsible editing rail, a peak-annotation toggle, a per-trace offset dock (`QNumInput`), and figure export (`FigureExportControls`) — backed by the `useSeries(id)` read hook already shipped in I3.3.

### The hard scope tension (OPEN DECISION for the human — see end of plan)

Issue #175 acceptance item 1 says the page renders *"all three representations (waterfall, heatmap, rail-collapsed)"* and item 2 wants a *"toggleable peak-tracking annotation layer."* But:

- **The render core has only the offset-waterfall representation.** `MultiTracePlot` has no heatmap. `GroupingMode` (`"bySample"|"byPhase"|"distinct"`, `lib/comparison/coloring.ts:32`) is a *coloring* axis, not a waterfall-vs-heatmap representation.
- **"rail-collapsed" is NOT a third plot representation** — the mockup comment (`series-builder.html:17–19`) is explicit: *"the offset waterfall is the default; the heatmap is a representation toggle; full-bleed is the rail's collapsed state (not a separate variant)."* So "rail-collapsed" is just the rail folding away (pure layout, fully in scope here).
- **Heatmap + cross-trace peak-*tracking* (the "Track reflections" switch) require `MultiTracePlot`/`MemberTraceLayer` internal changes** — which #175 itself carves out: *"If the peak-tracking layer needs `MultiTracePlot`/`MemberTraceLayer` internal changes, those land as an #172 [I3.2] follow-up, not here — the builder composes the render core."*

**Resolution this plan adopts (pending human confirmation):**
1. **Waterfall representation** — built (compose `MultiTracePlot`). ✅
2. **Rail-collapsed** — built (a layout toggle that folds the rail to full-bleed). ✅
3. **Peak *annotation* layer (ticks + labels)** — built, toggleable, via the render core's existing `showPeakTicks`/`showPeakLabels` props + `AnnotationToggles`. ✅ This satisfies "toggleable annotation layer" using what the core already supports.
4. **Heatmap representation** and **cross-trace peak-*tracking* (reflection-linking)** — **deferred to an I3.2 follow-up** (filed as a new issue), because both demand forbidden render-core internals. The builder ships a **representation toggle UI** whose "Heatmap" option is **disabled with a "coming soon" affordance** (or omitted) so the surface is structurally complete and the toggle lands without faking a render the core can't do.

This keeps I3.5a a faithful *compose-the-core* issue and honors the explicit "don't re-edit MultiTracePlot" constraint. **The human must confirm** whether shipping waterfall + rail-collapse + annotation-toggle (heatmap/tracking deferred) satisfies acceptance item 1, or whether the heatmap render-core work should be pulled into this issue's scope (which would make it a much larger, render-core-touching change — see heaviness note).

```tsx
/** Loaded body — composes the render core once `series` is present. */
function SeriesBuilderBody({ series: s }: { series: Series }): JSX.Element {
  // Members arrive sorted by display_order from the route; keep that order.
  const members: SeriesMember[] = s.members;
  const exposureIds = useMemo(
    () => members.map((m) => m.exposure_id).filter((x): x is number => x !== null),
    [members],
  );

  // Hydrate per-member trace / exposure / sample rows via the existing hooks.
  // Each hook is called exactly once at top level (Rules of Hooks); sampleIds
  // is derived from the exposures map AFTER it resolves.
  const traces = useMemberTraces(exposureIds);
  const exposures = useMemberExposures(exposureIds);
  const sampleIds = useMemo(
    () => Array.from(exposures.values()).map((e) => e.sample_id),
    [exposures],
  );
  const samples = useMemberSamples(sampleIds);

  // Coloring mode: seed from the series' persisted view default, else
  // "bySample" — matching effectiveGroupingMode's hard default
  // (effectiveGroupingMode.ts:29) so the builder's default coloring is
  // identical to Compare's. We do NOT reuse effectiveGroupingMode itself: it
  // is Comparison-typed and draft-aware, and this read surface has no draft
  // (persistence is a recipe edit → I3.5b). Local UI state only.
  const [groupingMode, setGroupingMode] = useState<GroupingMode>(
    (s.view_grouping_mode as GroupingMode | null) ?? "bySample",
  );

  // Pan/zoom q-domain. MultiTracePlot REQUIRES xDomain + onXDomain (NON-
  // optional props — MultiTracePlot.tsx:131-132, destructured with no
  // defaults at L182). Compare stores this in Zustand
  // `compareXDomains[comparisonId]`, but that Record is keyed by COMPARISON

  // :177) and Compare.tsx:402 — `(m: SeriesMember) => number | null`. Returns
  // null (NOT a -1 sentinel) for memberless/unresolved exposures.
  const sampleIdFor = useCallback(
    (m: SeriesMember): number | null => {
      if (m.exposure_id === null) return null;
      return exposures.get(m.exposure_id)?.sample_id ?? null;
    },
    [exposures],
  );

  // NOTE arg order: resolveDisplayLabels(members, exposures, samples)
  // (verified against lib/comparison/labels.ts — NOT members,samples,exposures).
  const displayLabelByMemberId = useMemo(
    () => resolveDisplayLabels(members, exposures, samples),
    [members, exposures, samples],
  );

  return (
    <ActiveBandProvider>
      <div className="flex-1 min-h-0 flex flex-col p-4 gap-3" data-testid="series-builder-plot">

            members={members}
            traces={traces}

            onXDomain={setXDomain}
            groupingMode={groupingMode}
            sampleIdFor={sampleIdFor}
          />
          <MemberMetaGutter
            members={members}
            panelHeight={0}
```
