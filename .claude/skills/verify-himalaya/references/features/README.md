# Himalaya Feature Map

How a user reaches each feature, the `bin/verify` commands that drive it, what to check, and its gotchas. Every recipe here was run against `make demo` data on 2026-11-19, and the corpus recipes again on 2026-11-20 after the demo gained bad frames. The ids below (experiment 1, sample 1 = `MO_H2O`, sample 3 = `MO_PEG5`) hold for a fresh `bin/verify seed`; on another DB, read them from `bin/verify api GET /api/samples`.

Names in `--name` come from `bin/verify snapshot --raw`. When a recipe stops matching, the UI changed: fix the entry in the same PR.

Keys are global unless noted; `?` opens the shortcut overlay on any page.

## Experiments home

- **Route:** `/experiments` (`/` redirects here). The top nav link "Experiments" returns here from anywhere.
- **Shows:** a timeline of experiments, each a button named `<name> <status> <data dir> <n> samples · <n> exp · <n> loads`.
- **Drive:**
  ```bash
  bin/verify open /experiments
  bin/verify click --role button --name "Demo (synthetic)"     # opens its workspace on the first unreviewed sample
  ```
- **Check:** `bin/verify api GET /api/experiments` (`ingest_status`, `stats`).
- **Palette:** ⌘/Ctrl+K (or `/` when no field has the cursor) opens the same `dialog "Commands"` as the workspace, here and in the New-experiment funnel. Groups: Experiments ("New experiment", hidden in the funnel; "All experiments", hidden on home; one `option "Open NAME"` per experiment) and App (Theme, Switch user, Keyboard shortcuts). Typing adds "Go to NAME, EXPERIMENT" rows for samples in every experiment, which open that sample in the workspace. ⌘K again or Esc closes it. The "Experiment 'X' not found." page's button opens it too.
  ```bash
  bin/verify press Meta+k
  bin/verify fill --role combobox --name "Command or sample" "peg5"
  bin/verify press Enter                                     # opens MO_PEG5 in the workspace
  ```

## Ingest funnel (new experiment)

- **Route:** `/experiments/new`, reached from the "+ New experiment" button on the home page. One screen: pick a folder, and it lists every setup under it (a beamtime date folder lists `setup1`, `setup2`, …; a setup folder lists itself). The folder field is `combobox "Data directory"`: typing a path starting with / or ~ lists matching folders in `listbox "Folders"`, each option named with what it holds ("setup1, setup", "beamtime-2026-11, beamtime, 3 setups"). Tab/Shift+Tab or ↑↓ move the highlight, Enter on a highlighted folder fills it in with a trailing slash (listing its subfolders), plain Enter adds the typed folder, Esc clears the highlight and then the list. `bin/verify fill` sets the value without typing, so drive completion with `press`. Under Details, `combobox "Data folder"` and `combobox "Integration folder"` complete folders the same way. A `textbox "Experiment name"` (`experiment-name`) above the list defaults to the picked folder's name. Each row is `checkbox "Include FOLDER"` (ticked unless that `data_dir` is already an experiment, then disabled with 'Already added as "X".'), the setup's folder name (`setup-folder`), `button "Details"` (folders, patterns, geometry; a layout edit recounts through `/api/fs/manifest`) and a summary line (`setup-summary`, e.g. "28 images · flight path 1.81 m · 2 without a trace yet"). The status above the list reads "Found N setups." The add button reads "Add experiment" with its keycap (⌘↵ on a Mac, Ctrl+↵ elsewhere). A setup whose integration layout was not recognised starts unticked; one copied before any `_tot.dat` exists still gets the SSRL layout when `analysis/automatic_analysis/tot_files` is there. Adding makes one experiment for the whole folder, with every setup that is not already an experiment; unticked setups are stored as hidden and not scanned. It then opens the workspace. A rescan adds any new setup folder that appears in the beamtime folder.
- **Needs a DB without the folder.** Start a second instance so the main demo is untouched. To see several setups, link the demo into a date-like folder:
  ```bash
  export DEMO_API_PORT=8081 DEMO_UI_PORT=5174 VERIFY_CDP_PORT=9334 VERIFY_STATE_DIR=scratch/verify-empty
  mkdir -p scratch/funnel-day && ln -sfn ../demo-experiment scratch/funnel-day/setup1 && ln -sfn ../demo-experiment scratch/funnel-day/setup2
  bin/verify seed --empty
  bin/verify open /experiments/new
  bin/verify fill --role textbox --name "Data directory" --value "$PWD/scratch/funnel-day"
  bin/verify wait-settle --timeout 30000
  bin/verify click --role checkbox --name "Add funnel-day/setup2"     # untick one
  bin/verify press Control+Enter                                     # adds funnel-day/setup1 and opens its workspace
  bin/verify check-truth
  bin/verify close && bin/verify stop                                # then unset the four variables
  ```
- **Check:** the workspace opens on `/experiments/<id>/workspace/…` with the status line counting the ingest ("Analyzing N of 28"), `bin/verify api GET /api/experiments` lists only the ticked setup, and `check-truth` passes on it once `ingest_status` is `complete`.
- **Gotchas:**
  - Press ⌘/Ctrl+Enter with focus on a checkbox or in the path field, not only on the page body: both handle Enter themselves, and the shortcut once re-ticked the focused checkbox or picked a folder suggestion instead. With the ⌘K palette open the shortcut belongs to the palette and adds nothing.
  - In the path field no suggestion is highlighted until ↓ moves into the list, so plain Enter adds the found setups (as ⌘/Ctrl+Enter does) instead of completing a subfolder; with nothing found it does nothing. Enter pressed before the typed path's own preview has landed ("Looking for setups…", or within the 200 ms debounce) adds once it lands, never the previous path's setups. Tab completes only a partly typed name (`…/day1/se` → `…/day1/setup1/`); once the typed folder is complete and the list holds only its subfolders, Tab moves focus on (type `/` or use ↓ to go deeper). Enter on a highlighted suggestion completes it with a trailing `/`.
  - A new experiment stores the real path of its folder, and the duplicate check resolves the picked folder's symlinks, so once a beamtime is added its setups read 'Already added'. To add the demo a second time, copy it (`cp -r`) instead of linking it.
  - The first scan runs on the server and reports over SSE, so a plain `wait-settle` returns before it ends. Poll `bin/verify api GET /api/experiments/<id>` for `ingest_status: complete`.

## Opening an experiment

- **Route:** `/experiments/<id>`. Clicking an experiment on the home page lands here, and it forwards at once to `/experiments/<id>/workspace` (the first unreviewed sample), whatever the ingest status. The old `/corpus`, `/config` and `/grouping` URLs under it do the same; `/experiments/new/config` goes to `/experiments/new`. There is no corpus, configuration, grouping review or scan-failed page (deleted 2026-11-21).
- **Check:** `bin/verify open /experiments/1` then `bin/verify snapshot` shows the workspace.

## Workspace (three-pane triage)

- **Route:** `/experiments/<id>/workspace/<sampleId>`; without a sample id it opens the first unreviewed sample (the first sample when all are reviewed). Reached by opening an experiment. It mounts outside the app shell, so there is no top nav; the "Himalaya" link in its header goes to all experiments. Above the sample list a notice (`workspace-notice`) holds the status line (`workspace-ingest-status`): ingest progress ("Reading files…", "Analyzing N of M", "Checking for new files…"), then "The last ingest failed." and "N images waiting for a trace · N analyses failed · N setup folders not recognised". Its `button "Details"` opens `dialog "Ingest problems"` (the stored ingest error, the setup folders a rescan skips because their layout is not recognised with `problems-add-setups`, which opens New experiment on the beamtime folder to add them with typed patterns, then one button per problem exposure, which opens its sample); the palette's "Show ingest problems" opens it too. While the first ingest has found no samples the main pane reads "No samples yet. They appear as the ingest reads the data folder." The palette carries "Rescan the data folder" (hidden while one runs; after a failed ingest or failed analyses it forces a full pass) and "Remove this experiment" (needs a user, hidden while an ingest runs): it opens `dialog "Remove experiment"`, and `button "Remove experiment"` deletes the experiment from the DB (not the files) and goes home. Other windows open on that experiment go home too, with the toast "This experiment was removed in another window." That is how a setup added with the wrong layout is fixed: remove it and add the folder again. To see problems, copy the demo, delete two `_tot.dat` files and overwrite one with junk, then add the copy in the funnel.
- **Shows:** the sample list (`list` in `navigation "Samples"`, the current row has `aria-current`; each row ends in the phase, "Form factor", or an `img "Unreviewed"` ○), the progress "N of M reviewed", the trace plot, the image thumbnails (`button "Image N"` / `"Image N, dropped"`, the shown one has `aria-current`; a bridged sample's strip then lists each same sample's frames in its own `section` under a heading naming that sample and, with more than one setup, its setup (`frame-group-header`, e.g. "A3 in Long pipe"), as `button "Image N of TITLE"`; picking one shows that frame (the Image panel's first row, "Sample", names the shown frame's sample and setup for every frame; on a short window, where Image starts folded, its folded header repeats that name for a bridged sample, `[data-section-folded]`, truncated), ←/→ step across the groups, and Drop acts on the frame's own sample; check-truth reads only the open sample's own cards), the ranked phase candidates (buttons with a keycap 1–9, `aria-pressed` when assigned; a custom index reads "Custom"; cubic candidates that coexist through the Bonnet relation sit under one `button "N Bonnet group … peaks"` header (`workspace-bonnet-group`) with their own numbered rows indented below it: a click or its number key ticks every member not yet in the call, or unticks all of them when all are in, as one undo step, and it reads `aria-pressed="mixed"` with a lighter tint while only some are in; the demo shows one on MO_PEG5's second frame, Im3m and Pn3m), the `button "0 No phase (form factor)"` row (`aria-pressed` when the frame is marked form factor) and the exposure details. `?exposure=<id>` on the route opens that frame. Above the plot sits the compare bar: one chip per comparison sample (its name is a button: a plain click hides or shows that sample's trace on the plot, `aria-pressed` while it is shown and named "NAME, hidden" while not; ⌘/Ctrl+click toggles it as the subtraction reference, marked `data-subtracted` and an accent border; a hidden chip dims its contents but keeps that border; then the scale applied as `×N`, or `×N matched` with `data-scale-source="matched"` when either frame lacks beam monitors; `button "Remove NAME"`), and "+ Compare". The plot's top-right corner holds the view switcher (`group "Plot view"`, `workspace-plot-view`): `button "Log plot"`, `"Linear plot"`, `"Log-log plot"` and `"q²I (Kratky) plot"` (shown as Log, Linear, Log-log, q²I), the active one `aria-pressed`. It is drawn at 40 % opacity (`plot-card-corner`) until the pointer is on it or a segment has keyboard focus; a click does not move focus to it. It sits below the peak-marker row and inside the y headroom the plot keeps above the data, so it covers neither. `V` steps to the next view and `Shift+V` back, wrapping. The palette's "Plot view" page lists the same views, the active one named "VIEW, Current" (typing "plot linear" at the top runs it directly); the choice is remembered per browser. With the switcher present the dark-image notice sits below it. The q²I view labels its y axis "q²·I"; the others have no y title. Hovering the plot shows `[data-role="q-readout"]` ("q … Å⁻¹ · d … Å"); peak markers are `[data-role="peak-glyph"] polygon[data-peak-key]` (`auto:3`, `manual:3`) in a row above the plot. Only while a subtraction reference is set, a toggle sits at the right end of the compare bar (`group "Subtraction"`, `workspace-subtraction-toggle`): `button "Raw"` and `button "Minus NAME"`, the active one `aria-pressed`. It is no taller than a chip, so nothing moves when it appears. Adding a comparison never sets the reference; ⌘/Ctrl+click on a chip (or the palette's "Subtract a comparison") sets it and switches to Minus. In Minus the plot draws the difference (`[data-role="difference-line"]`, accent, with a dashed `[data-role="zero-line"]`) in place of the trace and hides every other comparison: their chips and row marks read hidden, and a plain click on one goes back to Raw and shows it. The y axis is linear in Linear and q²I and an asinh "pseudolog" in Log and Log-log (ticks at 0 and ±10ⁿ, linear within about the high-q noise), cut off below the first peak. Peak clicks work the same. The palette's Plot group offers "Show minus NAME" / "Show the raw trace". A bridge says two samples are the same sample, and it lives in the palette only ("Same sample as…" opens page "Same sample as", leaving out this one and its group; "Not the same sample as NAMES" takes the open sample out). A bridge is not a comparison: bridged samples get no chip, take none of the five comparison slots, and Ctrl/⌘-click compares them like any other sample. The sample heading's row shows "Same as NAMES" (`data-same-sample`, truncated, hidden in narrow panes like the frame count). A bridged row in the sample list shows "⇄N" (`data-bridged`, titled and read as "N bridge(s)"). On the sample heading's row, right of the name, sits the label row (`workspace-labels`): one chip per label (`[data-label="NAME"]` with `data-label-state` `confirmed` or `suggested`; chips are pills; built-in system labels (Buffer, Calibrant, Empty capillary, matched ignoring case) carry `data-label-standard` and fixed colours: Buffer blue, Calibrant ochre, Empty capillary stone, shown capitalized; a suggestion is a dashed outline with no fill, and its `button "Confirm label NAME"` confirms it), `button "Remove label NAME"` on each, and `button "+ Label L"`. The row is one fixed-height line (`workspace-label-chips`); labels that do not fit go behind `button "N more labels"` ("+N", `workspace-labels-more`), which opens `dialog "More labels"` listing them with the same confirm and remove buttons (Escape closes it). Only shown pills carry `data-label`, so a label behind "+N" is found only after opening "More labels". A suggestion that cannot be confirmed reads ", suggested". Each pill has `data-label-color` (rose, plum, violet, blue, teal, green, ochre or stone; other labels default to violet). Blue, ochre and stone are kept for the system labels: user labels choose from the other five, the server refuses the three for them with a 400, and `GET /api/label-colors` leaves out stored rows that break this. Right-clicking a pill other than a system label opens `dialog "Colour of label NAME"`: a radiogroup of the five user swatches (`radio "Teal"`, …, the current one `aria-checked`) and, for a recoloured label, `button "Default colour"`. The colour belongs to the label name everywhere in the app and writes to the DB. The palette's "Label colours" page lists every label of the experiment except the system labels, whose colours are fixed (`PUT /api/label-colors` refuses them with a 400) ("N samples") and opens a one-field form (`dialog` named after the label, `combobox "Colour"`, ↑/↓ or a click on an `option` changes it, Enter applies). The palette's "Label" page lists the experiment's labels with their colour dot; Enter adds one, confirms a suggestion ("Suggested. Press Enter to confirm it.") or removes one already on the sample ("On this sample. Press Enter to remove it."). A typed name the experiment lacks offers `Create “NAME”`, which opens `dialog "New label"`: `textbox "Name"` and `combobox "Colour"` (starting on the first colour no label uses), Tab between them, Enter creates (writes the colour, then the label). `L` opens the picker (`dialog "Add a label"`, input `"Label name"`, focused and empty): it lists labels this browser added recently first (newest first, kept in localStorage `himalaya-ui:recent:label`, never attached to a sample), then the experiment's labels by use, then Buffer, Calibrant and Empty capillary; the palette's Label page uses the same order (its Label colours page stays in usage order). It matches misspellings, and a new label needs its `Create “…”` row. Enter adds the highlighted row; Backspace in the empty input removes the last confirmed label (both write to the DB). When the heading is under 34rem wide (the main pane at a 1024 px window), the "Image N of M" meta hides and `+ Label` shows only "+" and its keycap (its name stays "+ Label L"), and labels fold into "+N" before the sample name truncates. The picker opens under `+ Label`, right-aligned to it. Focus stays in its field: ↑/↓ and Tab/Shift+Tab (wrapping) move the highlight (`[aria-current=true]`); the options are not tab stops. The `/` filter matches labels as well as names. Without a username the chips show but nothing is editable.
- **Drive:**
  ```bash
  bin/verify open /experiments/1/workspace/1
  bin/verify press z                                  # next unreviewed sample (Gradescope's next ungraded)
  bin/verify press ArrowDown                          # next sample in the list
  bin/verify press ArrowRight                         # next frame
  bin/verify press 1                                  # toggle the top candidate on the shown frame (writes to the DB)
  bin/verify press 0                                  # mark the shown frame no phase (form factor); 0 again clears it (writes to the DB)
  bin/verify press x # drop the shown frame and show the nearest kept one (none left: it stays); x on a dropped frame restores it (writes to the DB)
  bin/verify press Control+z # undo the last edit (tick, 0, x, peak, custom index, label, label colour, bridge, experiment name or description, setup name or shown/hidden from the palette's Settings), jumping back to its sample and frame. It waits for queued edits to save, then reads the server and restores what the edit changed: toast "Undone: …", or "Already that way, nothing to undo: …" when there was nothing left to change. Undoing a peak edit that dropped the call also ticks the call's phases again on the re-fitted candidates, when they still fit. Undoing a confirmed or dismissed suggestion shows it as a suggestion again; a palette Create with a colour undoes in one press. Control+Shift+z (or Control+y) redoes. Blocked while the custom index is open. History is per tab and resets on reload or user switch
  bin/verify press /                                  # focus the filter; Esc leaves it and keeps the text, Enter opens the first match
  bin/verify press c                                  # open the compare picker (dialog "Compare with a sample"); type, Enter adds (it never subtracts by itself)
  bin/verify press Control+0                          # reset the zoom (⌘0 on a Mac); the palette's "Hide comparisons" replaces the old R key; V / Shift+V cycle the plot view
  bin/verify press l                                  # open the label picker under + Label (dialog "Add a label", field focused and empty); type, Tab/Shift+Tab or ↑/↓ move the highlight, Enter adds (writes to the DB), Esc closes
  bin/verify press Space                              # enlarge the shown frame's detector image (Space or Escape closes)
  bin/verify press i                                  # custom index in the tools pane's Assignment section, also opened by `button "Custom index I"` in that section's header (region "workspace-custom-index"): symmetry buttons, lattice slider and field; ← → nudge (Shift: ×10), a click on the plot puts the first order on the nearest peak, Enter adds to the call (writes to the DB), Esc cancels. While it is open the other single-key shortcuts do nothing, except ?
  bin/verify press ?                                  # shortcut list (dialog "Keyboard shortcuts"); also the ? button in the header
  bin/verify press Meta+k                             # command palette (dialog "Commands"), see Palette below
  ```
  Scroll on the plot zooms q (the zoom is kept across samples, clamped to each trace's q range and dropped when they don't overlap; Ctrl/⌘+0 resets it, double-click does not). `vesicles_ULV` in the demo stops at q = 0.2, so zoom past 0.2 and step to it to see the clamp. A click within 10 px of a peak disables or restores an auto peak and removes a manual one (marks are buttons named `Auto peak at q = … Å⁻¹`, `Auto peak at q = … Å⁻¹, off` or `Manual peak at q = … Å⁻¹`, so `bin/verify click --role button --name` hits one; auto and manual ids collide on real data, so check the result by source and id); a click elsewhere adds a manual peak (writes to the DB, needs a user and a kept frame). The picker only adds; samples already compared are not offered, and samples you compared recently in this browser come first (a per-browser list under `localStorage` `himalaya-ui:recent:comparison:<experiment id>`; it only orders the picker). Comparisons and the subtraction reference are saved on the sample (`GET /api/experiments/<id>/compares`, `PATCH /api/samples/<id>/compares` with `add`, `remove`, `subtraction`), so they come back when you return to it, other users see them live, and moving to another sample carries nothing over. A sample holds at most 5 comparisons, one per comparison colour: at the cap the picker and the palette's compare page say "5 comparisons at most. Remove one to compare another.", ⌘/Ctrl+click on another row shows that as a toast, and the PATCH answers 422. A comparison someone else added arrives hidden (its chip reads "NAME, hidden") and fetches no trace until you show it; ones you add start shown. Shown/hidden and Raw/Minus stay per browser tab and per sample, and are lost on reload. Minus stays on when someone else changes the subtraction; it then subtracts their choice. ⌘Z undoes adding or removing a comparison and setting or clearing the subtraction, but only while the sample still has what the edit left (it reads `GET /api/experiments/<id>/compares` first, so it never undoes over someone else's newer change); undoing a removed subtracted comparison restores it as the subtraction if none is set. ⌘/Ctrl+click on a sample-list row toggles it as a comparison without leaving the open sample (`bin/verify click --selector "[data-testid=workspace-samples] [data-sample-id='N']" --modifiers ControlOrMeta`; the same flag on a chip's name button toggles subtraction); a compared row shows a dashed line in its comparison colour (`data-compared`, `img "Compared"`). The palette's "Stop comparing with a sample" (page "Stop comparing") appears only while a comparison is shown. "Subtract a comparison" (page "Subtract", the current one hinted "Subtracted, Enter stops") is the keyboard way to pick or clear the subtraction reference; it appears while any comparison is shown. A hidden comparison's row mark dims (`img "Compared, hidden"`). Comparisons are scaled to the current trace by the ratio of transmitted flux (`I_signal` × exposure / counting time from each exposure's own .prp; the trace route returns them as `monitors`, one `_tot.dat` per exposure), and draw each sample's analyzed curve: the average of its selected images, or its one selected image. It falls back when either trace lacks monitors or has no positive flux; then it uses the median ratio over the top 15% of shared q with the current trace's own peaks masked. In the demo, `vesicles_ULV` against `buffer_blank` reads about ×1 (the demo jitters the APD dark rate, so expect a few percent of scatter); the high-q match gave ×3.
- **Indexing plot:** the tools pane's "Indexing" section plots peak q against q/q₁ for the open custom index, else the hovered candidate, else the ticked ones; its caption reads `PHASE a = X Å R² … N/M on peaks` (`d =` for Lamellar). With nothing hovered or ticked it draws empty axes. For a stored index it plots the peaks the backend claimed and its stored R²; M counts only the orders inside the trace's q range.
- **Custom index:** once added it is listed first in the Assignment list as "Custom" (it has no score) and ticked. `make verify-truth` adds a Hexagonal one on the confirmed sample, checks the ticked "Custom" row and the stored assignment, unticks it and checks again (step 10).
- **Palette:** `dialog "Commands"` with `combobox "Command or sample"`. Rows are `option`s grouped under This sample, Plot, Experiment and App; each has `data-palette-item` and is named "LABEL" or "LABEL, HINT". A row ending in › opens a page in place: the dialog is renamed to the page title ("Compare with", "Same sample as", "Tick", "Plot view", "Theme", "Label colour") and the bar shows the title and an argument field (`combobox "Sample"`, "Candidate", "View", "Theme", "Label"). "Tick a candidate" lists every ranked candidate ("Pn3m, a 104.2 Å"), not only the nine with keys. Typing at the top also searches inside the Compare, Same sample as, Tick and Plot view pages (rows named "PAGE › ITEM") and adds "Go to NAME" rows (first when the text is exactly a sample's name; at most 20); Theme and Label colours must be opened first. "Remove this experiment" only appears once typed, in red. With a user, the Experiment group has "Settings, Name, description": its page lists `option "Name, NAME"` and `option "Description, TEXT"` ("Description, None" when empty). Enter on a row opens a one-field form (`dialog "Name"` with `textbox "Name"`, or "Description"); Enter saves through `PATCH /api/experiments/<id>` only when the text changed, an empty name shows "Type a name." and saves nothing, and an emptied description is cleared. When the experiment has setups the hint reads "Name, description, setups" and the page adds one `option "Setup NAME, Shown"` (or "Hidden") per setup; Enter opens a two-field form (`textbox "Name"` with the folder name as placeholder, and an "In the workspace" choice of Shown/Hidden) that saves through `PATCH /api/setups/<id>`. Hiding the last shown setup shows "Keep at least one setup shown."; an empty name goes back to the folder name; showing a hidden setup starts a rescan. Hidden setups' samples drop out of the list, Z, progress and pickers. With two or more shown setups the sample list has a sticky `setup-header` row per setup. Esc goes back one level (restoring what was typed) and closes only at the top; Backspace in an empty field goes back; Tab/Shift+Tab and ↑/↓ move the highlight with wrap; held Enter, Esc and Backspace act once (repeats are ignored); ⌘K closes from anywhere. The compare and label pickers share the same list keys (`useListHighlight`).
- **Theme:** `<html>` and the workspace root carry `data-theme` (`system`, `light` or `dark`). `system` follows the OS; the palette's Theme page (Light, Dark, Follow the system) stores an explicit choice in localStorage (`himalaya-ui:theme`). Every page follows it: `<html>` carries the same attribute. A pick stored under the old key `himalaya-ui:workspace-theme` is moved to the new key on first read.
- **Switch user:** the palette's "Switch user" (named "Switch user, NAME") clears the stored user, so the onboarding name prompt appears. The header has no user control; that is deliberate (Jonathan, 2026-11-21).
- **Check:** `bin/verify check-truth --ui` reads the workspace first, the way a user moves through it: every row's status from one page (`workspace_text`, invariant `workspace_status_matches`), then a click on each row to read the frame it opens on (`views.workspace`, folded into `views_agree` and `analyzed_kept`), and the faint per-image lines under an average (`workspace_members`, invariant `plot_shows_selection`). If the shared tab is already on this experiment's workspace it reads that page in place, without a reload, so run it straight after an edit to catch a list that did not refresh; the output's `workspace_read` says `in place` or `loaded`.
- **Gotchas:**
  - Bad frames to drop (TRUTH's `drop` column): flares in `MO_H2O_37C` frame 2, `MO_F127` frame 1, `DOPC_H2O` frame 2 and `MO_AMP_10` frame 3; `MO_H2O` frame 3 (beam-off); `DOPE_H2O` frame 1 (missed capillary); and both frames of `leaked_capillary`. `bin/verify triage` drops them; `bin/verify triage --undo` keeps them again. A dropped thumbnail reads "Image 3, dropped" and the Kept cell "2 / 3". In the detector image a flare shows the sample's rings crossed by a bright horizontal streak through the beamstop, the beam-off frame is black with sparse speckle, and a missed capillary is dark apart from a glow around the beamstop.
  - On a dropped frame the candidates are disabled and number keys do nothing; restore the frame (x) first.
  - Keys do nothing before a username is set, or while focus is in a dialog or a text field.
