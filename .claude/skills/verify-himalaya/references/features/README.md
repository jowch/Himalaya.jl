# Himalaya Feature Map

How a user reaches each feature, the `bin/verify` commands that drive it, what to check, and its gotchas. Every recipe here was run against `make demo` data on 2026-11-19, and the corpus recipes again on 2026-11-20 after the demo gained bad frames. The ids below (experiment 1, sample 1 = `MO_H2O`, sample 3 = `MO_PEG5`) hold for a fresh `bin/verify seed`; on another DB, read them from `bin/verify api GET /api/samples`.

Names in `--name` come from `bin/verify snapshot --raw`. When a recipe stops matching, the UI changed: fix the entry in the same PR.

Keys are global unless noted; `?` opens the shortcut overlay on any page.

## Experiments home

- **Route:** `/experiments` (`/` redirects here). The top nav link "Experiments" returns here from anywhere.
- **Shows:** a timeline of experiments, each a button named `<name> <status> <data dir> <n> samples · <n> exp · <n> loads`.
- **Drive:**
  ```bash
  bin/verify open /experiments
  bin/verify click --role button --name "Demo (synthetic)"     # opens its workspace on the first unreviewed sample
  ```
- **Check:** `bin/verify api GET /api/experiments` (`ingest_status`, `stats`).

## Ingest funnel (new experiment)

- **Route:** `/experiments/new`, reached from the "+ New experiment" button on the home page. One screen: pick a folder, and it lists every setup under it (a beamtime date folder lists `setup1`, `setup2`, …; a setup folder lists itself). Each row is `checkbox "Add NAME"` (ticked unless that `data_dir` is already an experiment, then disabled with 'Already added as "X".'), `textbox "Experiment name"` (default `<folder>/<setup>`), `button "Details"` (folders, patterns, geometry; a layout edit recounts through `/api/fs/manifest`) and a summary line (`setup-summary`, e.g. "28 exposures · flight path 1.81 m · 2 without a trace yet"). The status above the list reads "Found N setups." The add button reads "Add N experiments" or "Add experiment" with its keycap (⌘↵ on a Mac, Ctrl+↵ elsewhere). A setup whose integration layout was not recognised starts unticked; one copied before any `_tot.dat` exists still gets the SSRL layout when `analysis/automatic_analysis/tot_files` is there. One setup opens its workspace at once; several go back to the home page.
- **Needs a DB without the folder.** Start a second instance so the main demo is untouched. To see several setups, link the demo into a date-like folder:
  ```bash
  export DEMO_API_PORT=8081 DEMO_UI_PORT=5174 VERIFY_CDP_PORT=9334 VERIFY_STATE_DIR=scratch/verify-empty
  mkdir -p scratch/funnel-day && ln -sfn ../demo-experiment scratch/funnel-day/setup1 && ln -sfn ../demo-experiment scratch/funnel-day/setup2
  bin/verify seed --empty
  bin/verify open /experiments/new
  bin/verify fill --role textbox --name "Data directory" --value "$PWD/scratch/funnel-day"
  bin/verify wait-settle --timeout 30000
  bin/verify click --role checkbox --name "Add funnel-day/setup2"     # untick one
  bin/verify press Control+Enter                                     # adds funnel-day/setup1 and opens its workspace
  bin/verify check-truth
  bin/verify close && bin/verify stop                                # then unset the four variables
  ```
- **Check:** the workspace opens on `/experiments/<id>/workspace/…` with the status line counting the ingest ("Analyzing N of 28"), `bin/verify api GET /api/experiments` lists only the ticked setup, and `check-truth` passes on it once `ingest_status` is `complete`.
- **Gotchas:**
  - Press ⌘/Ctrl+Enter with focus on a checkbox or in the path field, not only on the page body: both handle Enter themselves, and the shortcut once re-ticked the focused checkbox or picked a folder suggestion instead. With the ⌘K palette open the shortcut belongs to the palette and adds nothing.
  - In the path field no suggestion is highlighted until ↓ moves into the list, so plain Enter adds the found setups (as ⌘/Ctrl+Enter does) instead of completing a subfolder; with nothing found it does nothing. Enter pressed before the typed path's own preview has landed ("Looking for setups…", or within the 200 ms debounce) adds once it lands, never the previous path's setups. Tab completes only a partly typed name (`…/day1/se` → `…/day1/setup1/`); once the typed folder is complete and the list holds only its subfolders, Tab moves focus on (type `/` or use ↓ to go deeper). Enter on a highlighted suggestion completes it with a trailing `/`.
  - A new experiment stores the real path of its folder, and the duplicate check resolves the picked folder's symlinks, so once `setup1` is added `setup2` reads 'Already added'. To add the demo a second time, copy it (`cp -r`) instead of linking it.
  - The first scan runs on the server and reports over SSE, so a plain `wait-settle` returns before it ends. Poll `bin/verify api GET /api/experiments/<id>` for `ingest_status: complete`.

## Opening an experiment

- **Route:** `/experiments/<id>`. Clicking an experiment on the home page lands here, and it forwards at once to `/experiments/<id>/workspace` (the first unreviewed sample), whatever the ingest status. The old `/corpus`, `/config` and `/grouping` URLs under it do the same; `/experiments/new/config` goes to `/experiments/new`. There is no corpus, configuration, grouping review or scan-failed page (deleted 2026-11-21).
- **Check:** `bin/verify open /experiments/1` then `bin/verify snapshot` shows the workspace.

## Workspace (three-pane triage)

- **Route:** `/experiments/<id>/workspace/<sampleId>`; without a sample id it opens the first unreviewed sample (the first sample when all are reviewed). Reached by opening an experiment. It mounts outside the app shell, so there is no top nav; the "Himalaya" link in its header goes to all experiments. Above the sample list a notice (`workspace-notice`) holds the status line (`workspace-ingest-status`): ingest progress ("Reading files…", "Analyzing N of M", "Checking for new files…"), then "The last ingest failed." and "N exposures waiting for a trace · N analyses failed". Its `button "Details"` opens `dialog "Ingest problems"` (the stored ingest error, then one button per problem exposure, which opens its sample); the palette's "Show ingest problems" opens it too. While the first ingest has found no samples the main pane reads "No samples yet. They appear as the ingest reads the data folder." The palette carries "Rescan the data folder" (hidden while one runs; after a failed ingest or failed analyses it forces a full pass) and "Remove this experiment" (needs a user, hidden while an ingest runs): it opens `dialog "Remove experiment"`, and `button "Remove experiment"` deletes the experiment from the DB (not the files) and goes home. Other windows open on that experiment go home too, with the toast "This experiment was removed in another window." That is how a setup added with the wrong layout is fixed: remove it and add the folder again. To see problems, copy the demo, delete two `_tot.dat` files and overwrite one with junk, then add the copy in the funnel.
- **Shows:** the sample list (`list` in `navigation "Samples"`, the current row has `aria-current`; each row ends in the phase, "Form factor", or an `img "Unreviewed"` ○), the progress "N of M reviewed", the trace plot, the frame thumbnails (`button "Frame N"` / `"Frame N, dropped"`, the shown one has `aria-current`), the ranked phase candidates (buttons with a keycap 1–9, `aria-pressed` when assigned; a custom index reads "Custom"), the `button "0 No phase (form factor)"` row (`aria-pressed` when the frame is marked form factor) and the exposure details. `?exposure=<id>` on the route opens that frame; old `/sample/:id` and `/sample/:id/loupe` links redirect here and keep it. Above the plot sits the compare bar: one chip per comparison sample (its name is a button, `aria-pressed` when it is the subtraction reference, then the scale applied as `×N`, or `×N matched` with `data-scale-source="matched"` when either frame lacks beam monitors; `button "Remove NAME"`), and "+ Compare". There are no view buttons and no view key: the palette's "Plot view" page lists Log, Linear, Log-log and q²I, the active one named "VIEW, Current" (typing "plot linear" at the top runs it directly); the choice is remembered per browser. The q²I view labels its y axis "q²·I"; the others have no y title. Hovering the plot shows `[data-role="q-readout"]` ("q … Å⁻¹ · d … Å"); peak markers are `[data-role="peak-glyph"] polygon[data-peak-key]` (`auto:3`, `manual:3`) in a row above the plot. With a subtraction reference, `workspace-subtraction` under the plot is labelled "minus NAME". Bridging is in the palette only ("Bridge to a sample" opens a page of samples, leaving out this one and its bridges; "Take this sample out of its bridges"). Bridged samples always sit in the compare bar while either is open: their chip adds "bridged" and its remove button is `button "Remove bridge to NAME"`, which takes that sample out of the bridge (writes to the DB). A bridged row in the sample list shows "⇄N" (`data-bridged`, titled and read as "N bridge(s)"). On the sample heading's row, right of the name, sits the label row (`workspace-labels`): one chip per label (`[data-label="NAME"]` with `data-label-state` `confirmed` or `suggested`; chips are pills; built-in labels (Buffer, Calibrant, Empty capillary, matched ignoring case) are blue with `data-label-standard`, shown capitalized; a suggestion is a dashed outline with no fill, and its `button "Confirm label NAME"` confirms it), `button "Remove label NAME"` on each, and `button "+ Label L"`. The row is one fixed-height line (`workspace-label-chips`); labels that do not fit go behind `button "N more labels"` ("+N", `workspace-labels-more`), which opens `dialog "More labels"` listing them with the same confirm and remove buttons (Escape closes it). Only shown pills carry `data-label`, so a label behind "+N" is found only after opening "More labels". A suggestion that cannot be confirmed reads ", suggested". Each pill has `data-label-color` (rose, plum, violet, blue, teal, green, ochre or stone; built-ins default to blue, other labels to violet). Right-clicking a pill opens `dialog "Colour of label NAME"`: a radiogroup of swatches (`radio "Teal"`, …, the current one `aria-checked`) and, for a recoloured label, `button "Default colour"`. The colour belongs to the label name everywhere in the app and writes to the DB. The palette's "Label colours" page lists every label of the experiment ("N samples") and opens a one-field form (`dialog` named after the label, `combobox "Colour"`, ↑/↓ or a click on an `option` changes it, Enter applies). The palette's "Label" page lists the experiment's labels with their colour dot; Enter adds one, confirms a suggestion ("Suggested, Enter confirms it") or removes one already on the sample ("On this sample, Enter removes it"). A typed name the experiment lacks offers `Create “NAME”`, which opens `dialog "New label"`: `textbox "Name"` and `combobox "Colour"` (starting on the first colour no label uses), Tab between them, Enter creates (writes the colour, then the label). `L` opens the picker (`dialog "Add a label"`, input `"Label name"`, focused and empty): it lists the experiment's labels then Buffer, Calibrant and Empty capillary, matches misspellings, and a new label needs its `Create “…”` row. Enter adds the highlighted row; Backspace in the empty input removes the last confirmed label (both write to the DB). When the heading is under 34rem wide (the main pane at a 1024 px window), the "Frame N of M" meta hides and `+ Label` shows only "+" and its keycap (its name stays "+ Label L"), and labels fold into "+N" before the sample name truncates. The picker opens under `+ Label`, right-aligned to it. Focus stays in its field: ↑/↓ and Tab/Shift+Tab (wrapping) move the highlight (`[aria-current=true]`); the options are not tab stops. The `/` filter matches labels as well as names. Without a username the chips show but nothing is editable.
- **Drive:**
  ```bash
  bin/verify open /experiments/1/workspace/1
  bin/verify press z                                  # next unreviewed sample (Gradescope's next ungraded)
  bin/verify press ArrowDown                          # next sample in the list
  bin/verify press ArrowRight                         # next frame
  bin/verify press 1                                  # toggle the top candidate on the shown frame (writes to the DB)
  bin/verify press 0                                  # mark the shown frame no phase (form factor); 0 again clears it (writes to the DB)
  bin/verify press x                                  # drop the shown frame; x again restores it (writes to the DB)
  bin/verify press Control+z                          # undo the last edit (tick, 0, x, peak, custom index, label, label colour, bridge, experiment name or description from the palette's Settings), jumping back to its sample and frame. It waits for queued edits to save, then reads the server and restores what the edit changed: toast "Undone: …", or "Already that way, nothing to undo: …" when there was nothing left to change. Undoing a confirmed or dismissed suggestion shows it as a suggestion again; a palette Create with a colour undoes in one press. Control+Shift+z (or Control+y) redoes. Blocked while the custom index is open. History is per tab and resets on reload or user switch
  bin/verify press /                                  # focus the filter; Esc leaves it and keeps the text, Enter opens the first match
  bin/verify press c                                  # open the compare picker (dialog "Compare with a sample"); type, Enter adds; it subtracts too when nothing else is
  bin/verify press Control+0                          # reset the zoom (⌘0 on a Mac); the palette's "Hide comparisons" and "Plot …" replace the old R and view-cycling L keys
  bin/verify press l                                  # open the label picker under + Label (dialog "Add a label", field focused and empty); type, Tab/Shift+Tab or ↑/↓ move the highlight, Enter adds (writes to the DB), Esc closes
  bin/verify press Space                              # enlarge the shown frame's detector image (Space or Escape closes)
  bin/verify press i                                  # custom index in the tools pane (region "workspace-custom-index"): symmetry buttons, lattice slider and field; ← → nudge (Shift: ×10), a click on the plot puts the first order on the nearest peak, Enter adds to the call (writes to the DB), Esc cancels. While it is open the other single-key shortcuts do nothing, except ?
  bin/verify press ?                                  # shortcut list (dialog "Keyboard shortcuts"); also the ? button in the header
  bin/verify press Meta+k                             # command palette (dialog "Commands"), see Palette below
  ```
  Scroll on the plot zooms q (the zoom is kept across samples, clamped to each trace's q range and dropped when they don't overlap; Ctrl/⌘+0 resets it, double-click does not). `vesicles_ULV` in the demo stops at q = 0.2, so zoom past 0.2 and step to it to see the clamp. A click within 10 px of a peak disables or restores an auto peak and removes a manual one (marks are buttons named `Auto peak at q = … Å⁻¹`, `Auto peak at q = … Å⁻¹, off` or `Manual peak at q = … Å⁻¹`, so `bin/verify click --role button --name` hits one; auto and manual ids collide on real data, so check the result by source and id); a click elsewhere adds a manual peak (writes to the DB, needs a user and a kept frame). The picker only adds; samples already compared are not offered. Comparisons are scaled to the current trace by the ratio of transmitted flux (`I_signal` × exposure / counting time from each exposure's own .prp; the trace route returns them as `monitors`, one `_tot.dat` per exposure), and draw each sample's representative frame. It falls back when either trace lacks monitors or has no positive flux; then it uses the median ratio over the top 15% of shared q with the current trace's own peaks masked. In the demo, `vesicles_ULV` against `buffer_blank` reads about ×1 (the demo jitters the APD dark rate, so expect a few percent of scatter); the high-q match gave ×3.
- **Indexing plot:** the tools pane's "Indexing" section plots peak q against q/q₁ for the open custom index, else the hovered candidate, else the ticked ones; its caption reads `PHASE a = X Å R² … N/M on peaks` (`d =` for Lamellar). With nothing hovered or ticked it draws empty axes. For a stored index it plots the peaks the backend claimed and its stored R²; M counts only the orders inside the trace's q range.
- **Custom index:** once added it is listed first in the Call list as "Custom" (it has no score) and ticked. `make verify-truth` adds a Hexagonal one on the confirmed sample, checks the ticked "Custom" row and the stored assignment, unticks it and checks again (step 10).
- **Palette:** `dialog "Commands"` with `combobox "Command or sample"`. Rows are `option`s grouped under This sample, Plot, Experiment and App; each has `data-palette-item` and is named "LABEL" or "LABEL, HINT". A row ending in › opens a page in place: the dialog is renamed to the page title ("Compare with", "Bridge to", "Tick", "Plot view", "Theme", "Label colour") and the bar shows the title and an argument field (`combobox "Sample"`, "Candidate", "View", "Theme", "Label"). "Tick a candidate" lists every ranked candidate ("Pn3m, a 104.2 Å"), not only the nine with keys. Typing at the top also searches inside the Compare, Bridge, Tick and Plot view pages (rows named "PAGE › ITEM") and adds "Go to NAME" rows (first when the text is exactly a sample's name; at most 20); Theme and Label colours must be opened first. "Remove this experiment" only appears once typed, in red. With a user, the Experiment group has "Settings, Name, description": its page lists `option "Name, NAME"` and `option "Description, TEXT"` ("Description, None" when empty). Enter on a row opens a one-field form (`dialog "Name"` with `textbox "Name"`, or "Description"); Enter saves through `PATCH /api/experiments/<id>` only when the text changed, an empty name shows "Type a name." and saves nothing, and an emptied description is cleared. Esc goes back one level (restoring what was typed) and closes only at the top; Backspace in an empty field goes back; Tab/Shift+Tab and ↑/↓ move the highlight with wrap; held Enter, Esc and Backspace act once (repeats are ignored); ⌘K closes from anywhere. The compare and label pickers share the same list keys (`useListHighlight`).
- **Theme:** the workspace root carries `data-workspace-theme` (`system`, `light` or `dark`). `system` follows the OS; the palette's Theme page (Light, Dark, Follow the system) stores an explicit choice in localStorage (`himalaya-ui:workspace-theme`). Only the workspace has a dark theme.
- **Switch user:** the palette's "Switch user" (named "Switch user, NAME") clears the stored user, so the onboarding name prompt appears. The header has no user control; that is deliberate (Jonathan, 2026-11-21).
- **Check:** `bin/verify check-truth --ui` reads the workspace first, the way a user moves through it: every row's status from one page (`workspace_text`, invariant `workspace_status_matches`), then a click on each row to read the frame it opens on (`views.workspace`, folded into `views_agree` and `representative_kept`). If the shared tab is already on this experiment's workspace it reads that page in place, without a reload, so run it straight after an edit to catch a list that did not refresh; the output's `workspace_read` says `in place` or `loaded`.
- **Gotchas:**
  - Bad frames to drop (TRUTH's `drop` column): flares in `MO_H2O_37C` frame 2, `MO_F127` frame 1, `DOPC_H2O` frame 2 and `MO_AMP_10` frame 3; `MO_H2O` frame 3 (beam-off); `DOPE_H2O` frame 1 (missed capillary); and both frames of `leaked_capillary`. `bin/verify triage` drops them; `bin/verify triage --undo` keeps them again. A dropped thumbnail reads "Frame 3, dropped" and the Kept cell "2 / 3". In the detector image a flare shows the sample's rings crossed by a bright horizontal streak through the beamstop, the beam-off frame is black with sparse speckle, and a missed capillary is dark apart from a glow around the beamstop.
  - A phase call on a frame that is not the selected one selects it first, then adds the phase once the select is confirmed.
  - On a dropped frame the candidates are disabled and number keys do nothing; restore the frame (x) first.
  - Keys do nothing before a username is set, or while focus is in a dialog or a text field.

## Loupe and Focus (deleted)

Both pages were deleted on 2026-11-20 in favour of the workspace. `/sample/<id>` and `/sample/<id>/loupe` now redirect to `/experiments/<eid>/workspace/<id>`, and `/index/<exp>/<sample>` permalinks resolve to the same place. `check-truth --ui` reads only the workspace.
